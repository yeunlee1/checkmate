# 체크메이트 사용 안내.

CheckMate는 기존 검사를 실행하고 결과·증거·미검증 항목을 관리하는 로컬 데스크톱 앱이다. AI 모델을 직접 호출하지 않으며 API 키를 받지 않는다. Codex 또는 Claude Code가 자신의 구독으로 이 도구를 호출한다.

## 처음 실행.

개발 환경은 Node 24가 필요하다. 저장소 루트에서 `npm ci --ignore-scripts`, `node node_modules/electron/install.js`, `npx playwright install chromium`, `npm run build` 순서로 준비한다. `npm run desktop:dev`로 실제 앱을 실행한다. 개발 설치본에는 별도 Node를 동봉한다.

첫 화면의 로컬 저장소 준비는 체크메이트의 관리 SQLite와 실행 이력 폴더를 만든다. 일반 위치는 `%LOCALAPPDATA%/CheckMateData`이며 설정에서 현재 경로를 확인한다. 설치 프로그램의 `%LOCALAPPDATA%/CheckMate`와 분리해 제거 시 자료를 보존한다. 이전 개발 자료 경로는 자동 이동하지 않으며 `--data-dir` 또는 `CHECKMATE_DATA_DIR`로 그대로 선택할 수 있다. 대상 프로젝트의 DB와는 별개다.

프로젝트 추가에서 `checkmate/프로젝트.json`, `요구사항.json`, `검사항목.json`을 가진 폴더를 선택한다. 첫 연습에는 이 저장소의 `examples/대표검증`을 사용한다. `normal`은 정상 합성 앱, `defect`는 저장·권한 표식·화면·접근성·계산 결함을 의도적으로 넣은 앱이다. 외부 계정이나 업무 DB를 사용하지 않는다. 계산 결함 대조 예제는 Stryker 변이 점수와 구분한다.

프로필을 선택하고 계획 확인을 누른다. 명령·환경·쓰기 범위를 읽고 체크한 뒤 이 계획 승인을 누른다. 검사 실행이 활성화되면 실행한다. 검사 원본이나 실제 소스가 바뀌면 새 계획을 확인한다. AI에게 검사 실행을 맡기더라도 변경된 명령에 대한 확인은 별도다.

## 결과 읽기.

접수 성공과 검사 통과는 다르다. 최종 결과가 저장된 뒤 선택한 프로필의 판정을 읽는다. 실패는 관측한 불일치, 미완료는 취소나 필수 검사 누락, 미확인은 종료·환경·증거 등의 확인 부족이다. 범위 밖 요구사항은 완료로 표시하지 않는다.

요구사항 근거에서 관련 검사·누락·코드 경로를 본다. 검사 결과에서 기대와 관측을 비교한다. 증거를 열면 실제 파일의 해시를 다시 확인한다. 나중에 증거가 손상되면 과거 저장 판정이 통과여도 현재 재사용 판정은 미확인이다.

공개 텍스트와 HTML은 텍스트로 표시하고 실행하지 않는다. 공개 PNG는 캡처 보기로 연다. 형식이 맞는 디자인 JSON을 읽은 뒤 캡처에서 위반 위치 보기를 선택하면 해당 실행의 캡처에 위반 위치가 표시된다. 좌표나 크기를 확인할 수 없는 경우 위치를 추측하지 않는다. 제한된 자료의 본문은 화면과 MCP로 반환하지 않는다.

AI 수정 자료 묶음에는 실패와 누락, 코드 위치, 증거 ID, 재검사 안내가 있다. 표시된 구간만 복사되므로 전체 개수와 표시 개수를 확인한다. 같은 코드의 자동 재시도는 하지 않는다. AI가 수정한 뒤 새 계획으로 실행하며 기대값을 낮추거나 검사를 지워 통과시키지 않는다.

미검증 화면에는 처음 발견한 실행과 실제 보완한 실행을 함께 표시한다. 같은 공백은 중복으로 쌓지 않으며 관련 검사가 현재 근거로 통과해야 보완됨이 된다. 실패를 숨기거나 다른 프로필의 통과로 닫지 않는다. 실제 변이 검사의 실행과 점수 해석은 [검출력 사용법](검출력사용법.md)을 참고한다.

서비스 중단 뒤 정리가 미확인이면 같은 프로젝트의 새 실행을 보류한다. 실행이 만든 프로세스와 임시 자료를 직접 확인한 뒤 결과 화면의 정리 확인에 내용과 확인 여부를 기록한다. 이는 새 실행을 허용하는 사람의 확인이며 과거 미확인 결과를 통과로 바꾸지 않는다. CLI에서는 `acknowledge-cleanup <실행ID> --note <확인내용> --confirm`이다.

시험 DB가 필요한 명령은 `resources: ["postgres-test"]`를 선언한다. 로컬 Linux Docker를 실행한 상태에서 사용하며, 계획 화면에 새 일회용 PostgreSQL과 합성 자료의 변경·제거 범위가 표시된다. 연결 URL은 실행 중 해당 명령에만 전달한다. 기존 DB 주소와 볼륨을 등록하는 기능은 아니다.

실행 결과의 시험 DB 영역에서 생성과 제거 기록을 확인한다. 중단된 실행에 DB가 남았다면 대상 이름과 ID를 읽고 해당 실행의 시험 DB 정리를 선택한다. 소유권이 맞지 않으면 제거하지 않는다. DB 제거 뒤에도 명령 프로세스의 종료를 확인하고 정리 확인 기록을 남겨야 한다. CLI 조회는 `resources <실행ID>`, 제거는 `cleanup-resources <실행ID> --confirm`이다. MCP는 `list_run_resources`로 조회하며 수동 제거와 정리 확인은 사람용 입구에서만 수행한다.

## 이력과 자료 보관.

실행이력의 과거 보고서 가져오기는 아틀리에 검증 JSON의 안전한 단계 요약과 원본 해시만 저장한다. 원본 로그와 비밀 값은 복사하지 않는다. 원래 보고 상태가 passed여도 가져온 이력의 현재 판정은 미확인이다. 같은 보고서를 다시 가져오면 기존 이력을 재사용한다.

HTML 보고서 저장은 확정된 요약·요구사항·검사 결과를 UTF-8 단일 파일로 만든다. 긴 관측은 축약 표시를 유지하며 원본 캡처와 로그를 자동 포함하지 않는다. 기존 파일은 덮어쓰지 않는다. 파일을 직접 열어 읽거나 인쇄할 수 있다.

설정의 현재 자료 백업은 유휴 상태에서 관리 DB와 등록된 증거를 함께 검증하고 저장한다. 완료 표식이 없는 백업은 복구 대상으로 쓰지 않는다. 복구는 새 빈 폴더만 지원하며 현재 자료를 덮어쓰거나 자동 전환하지 않는다. CLI의 `--data-dir`로 복구한 자료를 확인한다. 연결 비밀은 백업에서 제외하고 복구한 저장소에서 새로 만든다.

## CLI와 MCP.

개발 CLI의 기본 진입점은 `node packages/engine/dist/명령.js`다. `--data-dir <절대경로>`와 `--json`을 명령 앞에 둘 수 있다. `--help`에서 명령과 필수 인자를 확인한다.

```powershell
node packages/engine/dist/명령.js doctor
node packages/engine/dist/명령.js setup --accept-local-storage
node packages/engine/dist/명령.js register C:/dev/E2E/examples/대표검증 --trust
node packages/engine/dist/명령.js projects --json
```

`inspect --project <ID> --profile normal`로 계획을 읽고 `approve --plan <ID> --fingerprint <지문> --confirm`으로 확인한다. `run --project <ID> --plan <ID> --request-id <새 UUID> --wait`로 실행과 확정 결과를 기다린다. 네트워크 재접속 시 같은 요청 ID를 재사용한다. 같은 ID를 다른 계획에 재사용하지 않는다.

`result <실행ID> --section summary`는 기본 8KiB 요약이다. `cases`, `requirements`, `gaps`, `repair-bundle`, `imported`는 상세 구간이다. `nextCursor`가 있으면 다음 구간을 요청한다. 기본 실패 상위 5건은 크기 예산에 따라 더 적게 나올 수 있으며 생략 개수를 함께 반환한다.

설정의 MCP 실행 정보를 선택한 AI 클라이언트 설정에 추가한다. 명령은 동봉 또는 개발 Node의 절대 경로이고 인자는 CLI 파일·자료 경로·`mcp`다. 다른 클라이언트 설정을 통째로 교체하지 않는다. stdio이므로 공개 HTTP 서버나 별도 유료 AI API는 필요 없다.

AI에는 다음 지시를 사용할 수 있다.

> CheckMate에서 등록 프로젝트와 계획을 확인하고, 승인된 범위만 실행해. 최종 확정 상태와 현재 증거를 확인해서 실패·미완료·미확인을 구분해 보고해. 실패하면 수정 자료 묶음과 필요한 증거 구간만 읽고, 검사와 기대값을 약화하지 말고 보완해. 바뀐 기준은 사람에게 확인받아.

## 현재 개발판의 경계.

같은 OS 사용자가 실행하는 악성 프로젝트 코드를 격리하는 샌드박스는 아니다. 신뢰하는 프로젝트를 등록한다. 앱 창 닫기는 검사 취소가 아니며 실행이력에서 다시 조회할 수 있다. 정리를 확인하지 못한 실행은 성공으로 복구하지 않는다.

아틀리에의 실제 PostgreSQL과 브라우저 업무 연결은 [연결 안내](아틀리에연결안내.md)의 대상 프로젝트 변경과 승인이 필요하다. D1 또는 모의 API 결과를 PostgreSQL E2E 통과라고 표시하지 않는다. 코드 서명과 깨끗한 Windows에서의 설치·업데이트 수용 시험은 공개 출시 조건이며, 서명 없는 개발 설치본을 정식 릴리스로 취급하지 않는다.
