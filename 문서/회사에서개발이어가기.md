# 회사에서 체크메이트 개발 이어가기.

2026-09-28 인계 기준이다. [다중 DB 지원 PR17](https://github.com/yeunlee1/checkmate/pull/17) 이후 Windows [자동 업데이트](자동업데이트.md)와 GitHub Actions 배포 흐름도 추가했다. 최신 통합 커밋은 GitHub `develop`의 실제 이력과 이동 ZIP의 최종 소스 표식을 대조한다. 소스 병합과 서명된 공개 릴리스는 별개다.

## 가져올 것.

- 소스·잠금 파일·설계·시험·Windows helper 원본은 [GitHub develop](https://github.com/yeunlee1/checkmate/tree/develop)에 있다. 원격 기본 `main`은 배포 기준이며 최신 개발 변경이 모두 들어 있는 브랜치가 아니다.
- 별도 이동 ZIP에는 현재 인계 설명, Git에 올리지 않는 피드백 기록과 선별한 합성 검증 결과, 오프라인 소스 복원용 `체크메이트소스.bundle`, SHA256 목록을 넣는다. 압축은 개발 인계용이며 설치본이나 검사 자료 DB의 백업이 아니다.
- `node_modules`, 빌드 산출물, Electron·Chromium·Docker 이미지, 개인 로그인과 전역 MCP 설정은 회사 PC에서 준비한다. 이 PC의 서비스 토큰·잠금·PID·SQLite/WAL·실제 고객 자료·환경 비밀은 가져오지 않는다.

## 회사 Windows 준비.

Git, PowerShell 7, Node.js **24.18.0 x64**를 준비한다. 저장소는 Node `>=24 <25`를 요구하고 CI는 24.18.0을 사용한다. GitHub에 게시하려면 회사 PC에서 본인 계정으로 별도 로그인한다. 개인 인증 파일을 ZIP에서 복원하지 않는다.

Windows helper는 `npm run build`가 추적된 `packages/engine/native/작업보호.cs`로 빌드한다. `%SystemRoot%/Microsoft.NET/Framework64/v4.0.30319/csc.exe` 또는 Framework 쪽 C# 컴파일러가 필요하다. 없으면 빌드의 실제 오류를 먼저 확인한다. 실행 파일만 다른 PC에서 복사해 준비 실패를 숨기지 않는다.

DB 프로필을 시험할 때만 로컬 Linux 컨테이너를 실행할 Docker가 추가로 필요하다. 회사의 사용 조건을 확인하고 [다중 DB 검사](다중DB검사.md)의 고정 이미지·SQL Server Developer 및 Oracle 조건을 따른다. 원격 Docker나 회사 업무 DB를 시험 대상으로 설정하지 않는다.

## GitHub에서 받기.

아래는 `C:/dev/E2E`가 아직 없는 경우다. 이미 있다면 먼저 그 폴더의 변경과 원격을 확인하며 덮어쓰거나 강제로 초기화하지 않는다.

```powershell
git clone --branch develop https://github.com/yeunlee1/checkmate.git C:/dev/E2E
Set-Location C:/dev/E2E
git status --short --branch
git log -1 --oneline
git config --local core.hooksPath .githooks
pwsh -NoProfile -File scripts/깃/제목검사검증.ps1
npm ci --ignore-scripts
node node_modules/electron/install.js
npx playwright install chromium
npm test
node packages/engine/dist/명령.js doctor --json
```

각 명령의 종료 코드를 확인하고 실패하면 다음 단계로 넘어가지 않는다. `npm test`가 빌드·타입·회귀를 함께 실행한다. 패키지·Electron·Chromium 다운로드에는 네트워크가 필요하며, 회사의 프록시나 인증 정보를 저장소에 커밋하지 않는다.

## 앱과 MCP 연결.

새 PC의 **CheckMate 제품 개발용 합성 자료**는 원본 아틀리에 이력과 구분한다. PowerShell에서 아래 환경 변수를 지정한 뒤 개발 앱을 백그라운드로 시작할 수 있다.

```powershell
$env:CHECKMATE_DATA_DIR = 'C:/dev/E2E/.runtime/회사개발자료'
Start-Process -FilePath (Get-Command node).Source -ArgumentList 'scripts/데스크톱개발.mjs' -WorkingDirectory (Get-Location).Path -WindowStyle Hidden
```

Electron 앱에서 자료 경로를 확인하고 로컬 저장소 준비를 진행한다. 화면 서버는 `http://127.0.0.1:5173`이며 브라우저만 연 화면은 Electron IPC가 연결된 제품 앱을 대신하지 않는다. 별도 HTTP 백엔드 서버는 없고 엔진은 로컬 IPC를 사용한다. 5173이 사용 중이면 소유자를 확인하며 다른 세션 서버를 종료하지 않는다.

MCP는 앱의 **설정 → MCP 실행 정보**를 해당 회사 PC 클라이언트에 추가한다. 아래는 위 경로를 사용한 구성 예시이며 전역 설정 파일 전체를 덮어쓰지 않는다.

```json
{
  "command": "C:/Program Files/nodejs/node.exe",
  "args": [
    "C:/dev/E2E/packages/engine/dist/명령.js",
    "--data-dir",
    "C:/dev/E2E/.runtime/회사개발자료",
    "mcp"
  ]
}
```

Node나 소스 경로가 다르면 실제 설치 경로로 바꾼다. 연결 후 `get_capabilities`의 `connection.dataRoot`와 `list_projects`의 ID·`realPath`를 함께 확인한다. MCP는 등록·승인·사람 정리 확인을 대신하지 않는다. 아틀리에 담당의 CheckMate 사용은 현재 MCP 전용이며, 이 문서의 CLI `doctor`는 CheckMate 자체 개발 환경 진단이다.

기존 서비스가 살아 있으면 새 소스 빌드만으로 교체되지 않는다. 진행 작업 종료와 정상 유휴 종료를 확인한 뒤 연결을 다시 열고 실제 기능을 조회한다. 소스 병합, 설치된 앱 버전, MCP가 연결한 자료 폴더를 별도로 확인한다.

## 현재 완료와 남은 일.

- PR12~16의 연결·공개 이미지·호환성·정리 안내 보완과 PR17의 PostgreSQL·MySQL·MariaDB·SQL Server·Oracle·MongoDB 격리 지원이 `develop`에 병합됐다. 고정 버전과 연결 계약은 [다중 DB 검사](다중DB검사.md)를 따른다.
- PR17 제품 소스는 로컬 회귀 43파일 357통과·2건너뜀, 실제 여섯 DB 수용, 공개 CLI의 단독 여섯 종류 및 혼합 한 건, Electron 수용과 Windows·Ubuntu CI를 통과했다. 회사 PC 재검증이나 모든 DB 버전·업무 검사의 통과를 뜻하지 않는다.
- 원본 아틀리에의 기존 실행은 정리 소유권이 불명확한 사람 확인 대기 상태다. 다른 PC에서 자원이 보이지 않는다는 이유로 해소하지 않는다. 원본 실행 ID·자료 경로·최신 피드백은 이동 ZIP의 비공개 인계 기록에 있다. 새 PC의 합성 제품 개발은 그 실행을 우회해 아틀리에를 다시 검사하는 수단이 아니다.
- 아틀리에 MCP의 자료 폴더 불일치와 PG 결과 수집기의 고정 8파일 제한은 아틀리에 담당과 후속 조율한다. 자체 native 브라우저 결과는 CheckMate 원본 실행 결과와 별도로 유지한다.
- 자동 업데이트의 합성 수용과 개발 설치본 제작은 [자동 업데이트](자동업데이트.md)를 따른다. 실제 인증서 서명·깨끗한 Windows 설치·공개 피드의 정식 릴리스·기존 설치본 교체는 별도다. 과거 개발 설치본을 최신 소스의 설치본으로 취급하지 않는다.

## 새 변경 시작.

`AGENTS.md`, [개발 현황](개발현황.md), [저장 및 연결 계약](저장및연결계약.md), [깃 관리](깃관리.md)를 먼저 확인한다. 다음 명령은 기존 변경이 없고 원격을 확인한 뒤 사용한다.

```powershell
git fetch origin
git switch -c "work/$(Get-Date -Format yyyy-MM-dd)-작업내용" origin/develop
```

변경 검증 후 한국어 설명의 커밋과 `develop` 대상 PR을 만들고 병합 커밋으로 통합한다. 현재 브랜치 보호가 강제된다고 가정하지 말고 실제 원격 설정을 확인한다. 다른 프로젝트·운영 DB·실제 고객 자료 수정은 CheckMate 로컬 합성 개발 승인 범위에 포함되지 않는다.

## GitHub에 접근하지 못할 때.

이동 ZIP을 풀고 `체크메이트소스.bundle`이 있는 폴더에서 다음처럼 **존재하지 않는 새 폴더**에 복원한다.

```powershell
git clone --branch develop ./체크메이트소스.bundle C:/dev/E2E
Set-Location C:/dev/E2E
git remote set-url origin https://github.com/yeunlee1/checkmate.git
git status --short --branch
git log -1 --oneline
```

ZIP의 최종 소스 커밋과 복원한 HEAD를 대조한다. GitHub 연결이 가능해지면 `git fetch origin`으로 이후 변경을 확인한다. bundle에는 소스 이력이 있지만 npm 패키지·브라우저·Docker 이미지는 없어 완전한 오프라인 설치본은 아니다. 동봉 결과 JSON은 읽기용 과거 증거이며 살아 있는 검사 자료로 복원하지 않는다.
