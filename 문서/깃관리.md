# 체크메이트 깃 관리.

개발은 `develop`, 배포 기준은 `main`이다. 2026-09-25 사용자 지정 참조 전략에 맞춰 적용한다. 과거 한글 전용 브랜치와 영문 접두어 금지 규칙은 아래 전략으로 대체하며 기존 커밋은 보존한다.

## 브랜치 흐름.

| 목적 | 흐름 |
|---|---|
| 일반 개발. | 최신 `origin/develop` → `work/YYYY-MM-DD-한국어작업내용` → `develop` 대상 PR → 병합 커밋. |
| 릴리스 통합. | 검증한 `develop` → `main` 대상 PR → 병합 커밋. |
| 배포 제작. | 확정한 `main` 커밋 → 별도 작업 폴더의 `build/<버전>` → 테스트·릴리스 빌드·산출물 확인 → 성공한 소스 커밋의 `v<버전>` 태그. |

현재 원격이 비어 있으므로 초기 설정 이력을 `main`과 `develop`의 같은 출발점으로 준비한다. 기존 `기본` 브랜치와 과거 커밋을 보존한다. 초기 구성 이후 일반 개발은 위 PR 흐름을 따른다. 릴리스 준비와 실제 설치본 게시·운영 반영은 구분하고 현재 사용자 승인 범위에서 진행한다.

## 작업 시작과 검사.

기존 변경을 확인한 뒤 원격을 갱신하고 `origin/develop`에서 작업 브랜치를 만든다. 브랜치를 바꾸려고 미커밋 파일을 삭제하거나 강제로 초기화하지 않는다.

```powershell
git status
git fetch origin
git switch -c "work/$(Get-Date -Format yyyy-MM-dd)-작업내용" origin/develop
git config --local core.hooksPath .githooks
pwsh -NoProfile -File scripts/깃/제목검사검증.ps1
```

`commit-msg`는 새 커밋의 제목을 검사한다. `pre-push`는 원격에 올릴 새 커밋을 검사하되 이미 다른 원격 브랜치에 있는 과거 이력을 다시 제한하지 않는다. 이력은 새 제목 규칙을 이유로 고치지 않는다. 훅 실행에 PowerShell 7과 Git이 필요하다.

GitHub Actions는 모든 브랜치의 push와 `develop`·`main` 대상 PR의 제목·커밋 제목을 검사한다. PR 제목 수정에도 다시 실행한다. 새 브랜치의 첫 push는 참조 전략과 같이 끝 커밋을 검사하고, 이후 push는 변경된 커밋 범위를 검사한다. 로컬 훅의 신규 커밋 검사와 함께 사용한다.

## 제목과 병합.

- 문서·파일명·브랜치·태그·커밋·PR에는 한글과 영어만 사용한다. 숫자·문장부호는 허용한다. 로컬 커밋 훅은 현재 브랜치와 커밋 문구를, 게시 훅은 대상 브랜치·태그 이름을 추가 검사한다. 자동 검사도 작업 브랜치 이름을 검사한다.
- 새 제목은 `fix: 검증 결과 조회 오류 수정`처럼 `<타입>: <한국어 설명>`으로 작성한다. 타입은 `feat`, `fix`, `docs`, `style`, `refactor`, `refact`, `test`, `chore`, `build`, `ci`, `perf`, `revert`를 사용한다.
- 범위는 `chore(빌드): 설치 경로 정리`처럼 선택적으로 붙인다. 타입 뒤에는 무엇을 바꿨는지 적는다.
- 검사기는 설명에 한글 4자 이상, 영문자 수가 한글 수 이하인지 확인한다. 과거 제목과의 호환 때문에 타입 없는 한국어 제목도 허용하지만 새 작업은 타입을 붙인다.
- PR은 병합 커밋으로 통합한다. `squash`·`rebase` 병합으로 바꾸지 않는다. 자동 영어 병합 제목 대신 `chore: 깃 관리 설정을 develop에 병합`처럼 작성한다.
- PR 본문에는 문제·변경 내용·실행한 검증·남은 제한을 한국어로 적는다. 기술명·명령·파일명은 필요한 경우 원래 표기를 유지한다.

## 원격 강제와 승인 범위.

문서와 로컬 훅·자동 검사만으로 GitHub의 직접 push가 금지되는 것은 아니다. 참조 저장소는 확인 당시 `main`·`develop` 브랜치의 `protected` 값이 false였다. 체크메이트도 이 작업에서 별도의 필수 승인자나 브랜치 보호 정책을 추가하지 않는다. 보호 여부와 실제 자동 검사 결과를 구분해 보고한다.

이 문서는 배포 버전·서명 수단·외부 업로드 대상을 새로 결정하지 않는다. DB 변경, 실제 자료 변경, 외부 배포는 해당 작업의 구체적인 범위에 대한 사용자 지시를 따른다.
