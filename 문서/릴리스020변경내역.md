# 체크메이트 v0.2.0 변경 내역.

여러 AI 세션과 작업 폴더가 같은 체크메이트를 사용할 때 실행 소유권과 승인 및 결과를 구분하고, 공유 자원의 실행 충돌을 차단한다. 저장 구조가 확장되므로 기존 자료의 전환은 자동 적용하지 않으며 공식 백업 및 사람 확인 절차를 따른다.

## 주요 변경.

- MCP 연결별 인증 주체와 실행 제어권을 확인한다. 사용자가 확인한 인계 후 이전 소유자의 제어권을 철회한다.
- 같은 저장소의 여러 작업 폴더를 구분하고 검사 목록, 계획, 승인, 실행 및 공백 이력을 분리한다.
- 동일 요청의 재전송은 기존 실행으로 연결하고 본문 변경이나 다른 소유자의 제어를 거절한다. 응답 유실과 unknown 상태를 새 실행으로 자동 재요청하지 않는다.
- 같은 호스트와 사용자 및 공유 잠금 경로에서 선언된 쓰기 경로와 자원 키의 경합을 차단한다. 실행 직전 소유와 검사 목록을 다시 확인한다.
- project-conflict와 catalog-stale 오류를 호출자에게 정확히 전달한다.
- 네이티브 PostgreSQL 실행 파일의 경로, 버전 및 지문을 승인에 고정한다. 실행과 정리 때 실제 프로세스와 소유 표식을 대조하고 확인되지 않은 자료를 보존한다.
- 지정한 검사 하나만 선택하는 실행을 지원한다. 같은 작업 폴더의 과거 공백은 원래 요구사항과 검사 및 명령 정의가 일치한 신뢰 통과 결과로만 해소한다.

## 사용과 전환.

기존 저장 버전1의 자료와 최종 결과를 보존한다. 저장 버전2로 전환하려면 유휴 및 정리 상태를 확인하고 검증된 백업을 만든 뒤 사람이 명시적으로 진행한다. 기존 설치본을 업데이트해도 각 AI의 MCP 실행 경로와 이미 실행 중인 서비스가 자동으로 바뀌었다고 가정하지 않는다.

실행 중이거나 unknown인 기존 실행은 인계와 정리 상태를 확인한 뒤 다룬다. 시간 경과만으로 잠금을 해제하거나 다른 세션의 실행을 강제 종료하지 않는다. 여러 PC나 선언되지 않은 자원까지 잠금이 보호하는 것은 아니다.

## 검증 근거와 제한.

개발 후보의 전체 빌드 및 타입 검사와 회귀517개, 별도 실제 PostgreSQL 두 클러스터의 동시 준비 및 정리, 독립 경합 검토12개를 확인했다. 서로 다른 단계의 통과 수는 합산하지 않는다. 이전 unknown 반례의 간헐적 실패는 이후 통과했으나 원인 미확정 기록을 유지한다.

최종 릴리스 후보의 자동 검사 및 설치 제작 결과는 해당 GitHub PR과 Actions 기록을 따른다. 실제 아틀리에의 설치 및 연결 전환, 정상 및 변이 사례의 효과 비교와 깨끗한 Windows PC에서의 수용은 별도 확인 대상이다.

자세한 개발 근거와 남은 작업은 [동시 사용 개선 인수인계](동시사용개선인수인계.md), [수정 요청 목록](../docs/수정요청목록.md), [추가 요청 대기열](../docs/추가요청대기열.md)에 정리했다.
