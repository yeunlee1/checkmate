## 현재 소스로 확인한 핵심.

1. 현재 앱은 PostgreSQL을 쓰지만 기존 네 업무 브라우저 E2E fixture는 D1을 사용한다.
2. 프론트의 로컬 백엔드4000과 기존 E2E 프론트3000이 고정돼 있다.
3. 과거 보고서 JSON에는 최종 프로세스 종료코드가 저장돼 있지 않다.
4. 직원 화면 E2E는 모의 API이며 실제 업무 브라우저 검증과 구분해야 한다.
5. 검증 조회 화면은 미완성·미커밋 초안이다.
6. 최신 대표 디자인은 라이트 시안이며 과거 네이비/베이지 설명보다 우선한다.

## 담당 세션 답변을 반영한 사항.

- 사람이 검사 목적·사전 조건·행동·기대·관측·판정·증거·미검증을 한국어로 읽는 화면이 핵심이다. 이를 결과-02와 공통 검사 계약에 명시했다.
- 첫 도입 순서는 과거 이력 읽기→빠른 검사→격리 PostgreSQL 대표1흐름이다. 이후 나머지 업무와 디자인을 확장한다.
- 테스트 연결 주소뿐 아니라 Better Auth origin·쿠키·프록시 전달을 함께 맞춰야 한다. 대상 프로젝트 연결 작업과 E2E 공통 도구 작업의 소유권을 나눴다.
- 치수0.1cm·빈 값/0, 연락처 정규화 중복, 보관 고객의 하위 변경, 견적50품목·안전 정수·위조 합계·중첩 세트 경계를 시나리오에 추가했다.
- 설계24.2절의 공통 폭1440/1024/768/390px와 시안 추가 검사1280/320px를 구분했다. 효과3단계 목표와 대표 HTML의 on/off 예시도 구분했다.
- 현재 역할 경계는 단일 매장의 owner/developer/staff다. 다중업체 격리나 미구현 재무 기능을 현재 검사로 포함하지 않는다. 재고는 후속이 아닌 제외 범위다.
- 실자료 PostgreSQL·원본 D1·백업과 기존 세션의 승인 경계를 유지한다. 이번 협의와 새 도구에 실행 승인을 상속하지 않는다.
- 열린 브라우저·네이티브 앱·Pen 조작을 하지 않는 사용자 경계를 전달받아 기록했다. 이번에는 테스트도 실행하지 않았다.

## 초안 검토와 수정.

담당 세션은 최초 초안에 P0 이력·quick 설계 자체를 막는 치명적 사실 오류는 없다고 답했으나 실행 연결 전 수정3건을 요구했다. 해당 세션은 구현/시험 승인이나 도구 보안 통과를 판정한 것이 아니다.

| 지적 | 반영 위치 | 수정 내용 |
|---|---|---|
| 실제 설정 파일 자동 로딩과 고정 포트. | 요구사항6·8절, 개발설계5절. | 기존 서버 명령을 단순 포장하지 않고 가상 설정/포트 실행 경로를 분리. 실자료 fallback 금지, Origin 전달·검사 유지. |
| 기존 PG fixture의 자원 소유권 미연동. | 요구사항 실행-01·6절, 개발설계4·5·8절. | runId/소유 토큰/내구성 등록·종료 확인. Node 종료와 컨테이너 종료 구분, 불확실한 정리는 미확인. |

비차단 제안도 반영했다. M0/M1/M2 제공 수준, quick의 해당 없음 조건, 실행별 비영속 브라우저와 가상계정, 원본 보고서의 실제 실행 연결 및 기존 잠금 존중, history와 quick의 파일 쓰기 차이, 대표 시안 수용과 전체 접근성 합격의 구분이다.

## 최종 사실 확인.

담당 세션은 수정본 두 문서를 다시 읽고 현재 소스와 대조해, 사실 확인 범위에서 남은 차단 사항과 추가 수정이 필요한 사실 오류를 발견하지 못했다고 회신했다. 사용자 최종 승인, 구현 완료, 실행/보안 검증 통과, DB 쓰기 승인과는 별개라고 명시했다.

상대 세션이 제시한 SHA256과 E2E 세션에서 계산한 실제 파일 SHA256이 일치했다.

| 개발설계.md | `53E1604F2B7C36D326C4AD1F28D2E8DA950B8B9EFA9E59EE2EB0C55C77C35092` |

문서4개의 로컬 링크·코드블록 종결·UTF-8 대체문자 부재와 요구사항16개의 ID 중복 여부를 검사했다. 이는 문서 무결성 확인이며 프로그램 테스트나 앱 회귀 검증이 아니다.

## 현재 확인한 실행 환경.

대상 HEAD는 `5d661f7`이며 기존 미커밋 인수인계·Pen·조회 초안은 보존했다. 이번 E2E 세션에서 HTTP로 기존 `http://127.0.0.1:3000/login`과 `http://127.0.0.1:4000/api/health`의200 응답을 확인했고, 후자는 `database=connected`였다. 서버를 새로 시작하거나 재시작하지 않았다. 이 확인은 로그인·DB 엔진 일치·업무 회귀를 증명하지 않는다.

E2E 프로그램은 설계 단계라 실행 서버와 CLI/MCP는 아직 없다. 이번 산출물은 Markdown 문서다. 기존 아틀리에 앱을 실행 중인 상태로 유지했다.
