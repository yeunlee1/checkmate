# 격리 시험 DB.

체크메이트는 프로젝트 명령이 `resources: ["postgres-test"]`를 선언한 경우 실행마다 새 PostgreSQL 컨테이너 하나를 생성한다. 명령 여러 개가 같은 자원을 선언하면 해당 실행 안에서 공유한다. 선언하지 않은 명령에는 연결 환경을 전달하지 않는다. 자원 선언은 소스와 계획 지문 및 승인 범위에 포함한다.

로컬 Linux Docker가 필요하다. PostgreSQL 17 alpine의 이미지 digest를 고정하며 loopback 동적 포트와 컨테이너 내부 tmpfs를 사용한다. 부모 서비스가 생성 전에 SQLite `resources`에 실행 ID·자원 ID·소유 토큰 해시·컨테이너 이름·이미지·로컬 endpoint와 daemon ID를 저장한다. DB 암호와 연결 URL, 토큰 원문은 기록하지 않는다. 현재 고정 이미지는 다음과 같다.

```text
postgres:17-alpine@sha256:b0f9560a2de083e2cc7382e75f808c7381a32852a7ec49117deedb300e552b24
```

어댑터는 `CHECKMATE_PG_MANAGED=1`, `CHECKMATE_PG_ADMIN_URL`을 실행 환경에서 읽는다. 사용자 설정에서 이 예약 값을 덮어쓸 수 없다. 어댑터는 이 컨테이너 안에서만 임시 DB를 만들고 필요한 마이그레이션과 합성 자료 쓰기를 수행한다. 연결이 없거나 잘못됐을 때 기존 DB 또는 자체 Docker 실행으로 후퇴하지 않는다. 부모가 최종 컨테이너 제거를 담당한다.

명령 출력의 동적 비밀을 가리고 증거 등록 전에 알려진 비밀 바이트를 검사한다. 비밀이 발견된 증거는 등록과 공개를 거절하고 해당 실행을 검증 통과로 사용하지 않는다. 프로젝트 코드의 임의 파일 쓰기를 차단하는 OS 샌드박스는 아니며, 프로젝트가 직접 쓴 미등록 파일을 자동 삭제하지 않는다. 인코딩·압축·가공된 모든 비밀을 탐지하는 DLP 기능으로 해석하지 않는다.

부모가 확인한 컨테이너 ID·이름·소유 라벨·daemon·이미지·마운트·포트와 실제 준비 결과만 환경 검증의 근거가 된다. 어댑터의 자원 이벤트는 부모 소유권 검증을 대신하지 않는다. 정상 종료·실패·취소·준비 실패 후 소유 자원을 정리하고 실제 부재를 확인한다. 확인할 수 없는 상태는 미확인으로 보존한다.

부모 강제 종료에서는 자동 정리를 보장하지 않는다. 새 서비스는 중단된 실행을 미확인으로 확정하고 자동 재실행·추정 회수를 하지 않는다. 사람이 실행 결과의 시험 DB 기록을 확인해 그 실행만 정리한다. 다른 세션이나 이름 패턴에 맞는 컨테이너를 일괄 제거하지 않는다. 과거 판정은 수동 정리 뒤에도 그대로 유지한다.

생성 의도를 저장한 뒤 Docker 호출 직전에 `creating`을 기록한다. 생성 호출 결과가 불명확하고 아직 ID를 확인하지 못했다면, 잠시 컨테이너가 보이지 않아도 정리 완료로 바꾸지 않는다. 뒤늦게 같은 이름이 나타나면 전체 소유 정보를 검증한 후 ID를 복구한다. `cleaned`가 아닌 기록이 있으면 같은 작업 경로의 다음 실행을 차단한다. Docker 호출에는 시간 제한과 취소 신호를 전달하며, 정리는 취소된 검사와 별도 제한 시간으로 수행한다.

`--tmpfs`로 만든 실제 Docker 컨테이너는 `inspect.Mounts`가 빈 배열일 수 있다. 설정의 마운트·포트 전체 구조를 검사하고 준비 단계에서 컨테이너의 `/proc/self/mountinfo`에 해당 경로의 tmpfs와 `rw,nosuid,nodev`가 있는지 확인한다. 추가 바인드·볼륨·포트와 원격 Docker endpoint는 거절한다.

시험이 만든 잔존 자원은 0개였다. 응답 유실과 중지 실패는 실제 컨테이너에 합성 호출 오류를 주입한 시험이며, 실제 daemon 장애나 전원 손실을 재현했다는 뜻은 아니다. 부모가 중단 중 관측하지 못한 소스 지문은 `null`로 보존하고 현재 소스를 별도로 재조회했다. 앞선 시험 도구 오류의 실패 보고서는 보존했다.

Windows helper의 환경 전달을 명령줄에서 비공개 stdin 프레임으로 변경한 `2161815`에서도 같은 실제 수용을 다시 통과했다. 결과는 `.runtime/검증/격리DB/cbb791c9-0f16-4014-a1c7-c1f5626ed015/결과.json`이며 잔존 자원은 0개다. 프레임은 4바이트 길이와 최대 1MiB UTF-16LE 환경 블록을 사용한다. 입력 손상과 EOF는 자식 생성 전에 거절하고, 생성 후 부모 종료는 기존 Job 정리로 처리한다. 환경값 원문과 Base64가 자기 helper 명령줄에 없다는 실제 회귀를 포함한다.

실제 Electron의 선택 정리 수용 `b081557c-9d9d-4aa1-9c99-56ef48dc9938`에서 승인 전 실행 차단, 자원 목록, 정리 동의 전 버튼 비활성, 해당 DB 제거, 별도 정리 확인과 과거 미확인 판정 보존을 조작했다. 네 화면 크기 및 확대 조건의 가로 넘침과 axe 위반은 없었다. 해당 UI 검사는 보안 전달 수정 전이며 이후 설치된 앱에서는 수정된 전달 경로로 실제 업무 실행과 자원 제거를 다시 확인했다.
