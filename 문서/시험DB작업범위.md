# 체크메이트 시험 DB 작업 범위.

2026-09-25 사용자 확인을 위한 실행 계획이다. 현재 상태는 승인 대기이며 DB 작업을 실행하지 않았다. 범위는 첫 SQLite 저장·실행 서비스 구현과 그 회귀 시험이다.

## 대상과 조건.

- 새 시험 DB만 `C:/dev/E2E/.runtime/검증/sqlite/<시험 UUID>/checkmate.sqlite`에 생성한다. 시험 실행이 만든 UUID 폴더와 소유 표식을 확인하며 기존 폴더를 재사용하지 않는다.
- 개발자가 작성한 합성 프로젝트·검사·실행 결과만 저장한다. 시험당 DB 하나에 최대 2,000개 합성 행을 목표로 작은 자료를 사용한다. 부하 시험은 별도 범위다.
- 실제 사용자 관리 DB, `%LOCALAPPDATA%/CheckMate/`, 아틀리에의 DB, 외부 PostgreSQL, 운영·고객 자료는 접근 대상이 아니다.

## 허용을 요청하는 작업.

1. 빈 시험 DB에 스키마 버전 1을 적용한다. 대상 테이블은 `schema_migrations`, `projects`, `workspaces`, `catalogs`, `definitions`, `requirement_checks`, `plans`, `approvals`, `runs`, `requests`, `steps`, `case_results`, `evidence`, `gaps`, `resources`, `events`, `audit_events`다. 초기 구현에 필요한 테이블부터 같은 계약으로 추가한다.
2. SQLite의 WAL, foreign_keys, busy_timeout, synchronous 설정을 적용하고 합성 행을 INSERT한다. 실행 상태·결과 확정·공백·자원 정리 시험에서 이번 시험의 ID에 해당하는 행만 UPDATE한다.
3. FK·중복 요청·롤백·복구·손상 탐지를 검증한다. DELETE는 이번 시험의 합성 ID 조건으로 제한한다. 마이그레이션 checksum 등 불변 이력의 변조 시험은 별도 새 손상 시험 DB에서만 수행한다. 기존 DB의 ALTER·DROP·TRUNCATE는 이 범위에 포함하지 않는다.
4. 시험용 새 DB의 백업·재개방·강제 중단 복구를 확인한다. 백업도 같은 UUID 폴더 아래에만 만든다. 종료가 확인된 해당 시험 연결·직접 생성 자원만 정리한다.
5. 시험 종료 후 소유 표식과 정규화한 절대 경로가 위 시험 루트 안인지 확인하고, 해당 UUID 폴더의 DB·WAL·SHM·백업·시험 자료를 삭제한다. 경로·소유권이 불확실하면 삭제하지 않고 보고한다.

## 예상 영향과 실행 기록.

변경 대상은 이번 개발 시험이 새로 만드는 로컬 일회용 자료다. 기존 사용자의 저장 자료에는 영향이 없다. 실패한 시험도 합성 자료만 남으며 보존 여부를 기록한다. 자동 정리 코드는 경로 검증 후 실행한다.

승인 후 실제로 사용한 테이블·시험 명령·결과를 개발 현황에 기록한다. 범위를 벗어나는 새 DB·기존 데이터 변경·스키마 교체가 필요하면 추가 실행 전에 다시 확인한다. 이 문서만으로 승인이 발생하지 않는다.
