# 체크메이트 개발 현황.

2026-09-25 첫 기반 개발을 시작했다. 로컬 폴더는 `C:/dev/E2E`로 유지한다. 설계는 [구현 기준](구현기준설계.md)과 [저장 및 연결 계약](저장및연결계약.md)을 따른다.

## 구현한 범위.

- Node.js 24·TypeScript·npm workspaces와 고정 의존성.
- Zod 결과 계약, 필수 검사·계획 연결·종료코드·소스·환경·증거·정리·확정 여부를 확인하는 판정.
- CLI 환경 진단과 결과 JSON의 읽기 전용 형식/판정 검사.
- 등록된 명령의 직접 자식 프로세스 실행, 실제 종료코드·시간 제한·취소·출력 상한·시작 실패 구분.
- 64KiB UTF-8 NDJSON 이벤트의 버전·실행 ID·순서·형식 검증과 증분 읽기.
- 증거 파일의 안전한 상대 경로·링크·크기·SHA256·읽는 도중 변경 검사.
- SQLite 스키마 버전1의 17개 테이블, 연결 설정, 초기화 트랜잭션, 재개방 무결성·버전·checksum 검사.
- 내부 실행 저장소의 계획 등록·요청 중복 방지·작업 폴더 실행 잠금·상태 전이·케이스와 결과의 원자적 확정·이력 페이지.
- 내부 서비스의 직렬 실행·중복 실행 방지·대기 중 즉시 취소·실행 중 취소 전달·계획 입력 고정·완료 핸들 해제.
- Windows와 Linux의 빌드·자체 회귀를 실행하는 GitHub Actions 구성. Linux 시험은 엔진 기반의 이식성 확인이며 Linux 설치 앱 지원을 뜻하지 않는다.

현재 버전 표기는 `0.1.0-alpha.1`이며 배포 설치본을 만들거나 게시한 상태는 아니다. 저장·서비스는 내부 API 기반이며, 인증된 사용자별 broker·IPC·프로젝트 등록 화면·공개 run 명령·MCP·Electron UI·설치본은 아직 구현하지 않았다. CLI의 database/project-runs 미제공 표시는 사용자용 명령의 상태다. 제목 검사 통과와 제품 기능 검증은 구분한다.

## 직접 확인하는 명령.

```powershell
npm ci --ignore-scripts
npm test
node packages/engine/dist/명령.js doctor --json
node packages/engine/dist/명령.js report validate '결과.json' --json
```

직접 실행한 Node 명령의 stdout에는 JSON 하나만 출력한다. `npm run checkmate -- doctor --json`도 사람이 사용할 수 있지만 npm 자체 안내가 앞에 붙으므로 프로그램 연동에는 직접 Node 명령을 사용한다.

`report validate`의 종료코드0은 파일의 형식과 판정 조건이 일치한다는 뜻이다. 파일이 실제 시험에서 생성됐다는 인증이나 대상 앱 통과를 뜻하지 않는다. 응답에 `evidenceAuthenticated: false`와 파일에 기록된 판정을 함께 표시한다. 실제 검사 명령의 완료/종료 규칙은 추후 run 명령에 적용한다.

## 검증과 제한.

Windows의 `npm test`에서 빌드, 소스·시험 코드의 타입 검사, 9개 시험 파일의 116개 회귀를 통과했다. 거짓 통과, 누락, 소스 변경, 과거 결과, 중복·계획 밖 ID, 비영 종료, 시간 초과, 취소, 부모 환경 차단, 손상 JSON·UTF-8, 과대 파일, 출력 유출 경계를 검사한다. SQLite 시험은 사용자 승인 범위의 새 합성 DB만 생성·갱신하고 소유 표식과 실제 경로를 확인한 뒤 정리한다. 코드 기준 커밋은 `6db3632`이며 같은 커밋의 Windows/Linux 원격 기반 검사와 한국어 제목 검사도 통과했다.

실행 통합 시험은 실제 Node 자식 → NDJSON 이벤트 → 증거 해시 → 실행 서비스 → SQLite 확정 → DB 재개방의 연결을 확인한다. 실제 종료코드0과 정상 증거는 passed, 성공 이벤트가 있어도 실제 종료코드9는 failed, 증거 변조는 unknown으로 보존했다. 이는 통제한 합성 검사이며 아틀리에나 외부 대상 앱의 E2E 통과를 뜻하지 않는다.

첫 독립 검토에서 마지막 파일 경로 검사에 관측된 크기·시간 변경을 비교하지 않는 P1 결함을 재현했다. 해당 비교를 보완하고 실제 추가 쓰기·같은 크기 덮어쓰기 회귀를 실패 후 통과로 확인했다.

저장·서비스 독립 검토에서는 P2 결함 네 건을 재현해 수정했다. 대기 실행을 취소하면 기존에 등록한 완료 대기도 즉시 해소되며, SQLite 정수 의미 열은 잘못된 자료형을 거절한다. 이력은 초·밀리초 표기가 섞여도 같은 시각 기준으로 정렬·페이지 조회하고, 실제 WAL 경합의 확장 오류는 재시도 가능한 storage-busy로 분류한다.

최종 독립 검토는 고정 커밋 `6db3632`에서 해당 수정과 직접 영향 범위를 확인했다. 대상 회귀 53개와 별도 재현 4개를 합친 57개 시험 및 루트 타입 검사를 통과했고, P2 네 건의 해결과 증거 P1 회귀 유지를 확인했다. 이 57개는 전체 116개와 일부 겹치는 별도 검토 근거이며 합산하지 않는다. 지정 범위에서 추가 결함은 발견하지 않았다. 코드·검증·병합 상태는 [PR #2](https://github.com/yeunlee1/checkmate/pull/2)에서 확인한다.

SQLite의 문자 기본키에도 NOT NULL을 명시하고 직접 NULL 삽입 거절을 검증했다. SQLite 일반 테이블의 기본키와 CHECK에는 NULL 관련 예외가 있으므로 열 제약과 도메인 검증을 함께 사용한다. [SQLite 제약](https://www.sqlite.org/lang_createtable.html#the_primary_key). 연결과 트랜잭션은 [better-sqlite3 API](https://github.com/WiseLibs/better-sqlite3/blob/master/docs/api.md)의 동기 트랜잭션·rollback·PRAGMA 계약을 확인했다.

TypeScript의 Node 전역 타입은 engine 설정의 `types: ["node"]`로 명시했다. 한글 파일명의 외부 source map 경로 해석 경고는 inlineSourceMap·inlineSources 설정으로 해결했다. Context7에서 TypeScript 공식 자료를 확인한 뒤 적용했다. [types 설정](https://www.typescriptlang.org/tsconfig/types.html), [inlineSourceMap](https://www.typescriptlang.org/tsconfig/inlineSourceMap.html).

작업 실행기는 직접 자식의 종료만 확인한다. 손자 프로세스·Docker·서비스 장애 후 소유권 복구·앱 창 종료 후 지속 실행은 아직 제공하지 않는다. 다른 프로젝트 명령이나 실제 아틀리에 시험을 실행하지 않았다. HTTP 서버와 UI가 없는 단계이므로 접속 URL도 아직 없다.

다음 단계는 실제 프로젝트 원본·계획·승인 연결, 증거 ready 등록과 현재 무결성 재확인, 사용자별 broker·IPC·CLI/MCP 연결이다. 현재 내부 executor는 신뢰된 모듈의 관측 결과를 받아 저장한다. 증거 등록·백업/복구·장애 후 실행 회수·앱 종료 후 지속 실행은 완성되지 않았다. SQLite에17개 테이블이 있다는 사실을 모든 업무 기능의 구현으로 표시하지 않는다.

사용자가 체크메이트 로컬 개발 DB 변경을 포괄 승인했으므로 이 범위의 후속 개발은 반복 확인 없이 진행한다. 아틀리에·운영·실제 고객 자료 변경 승인은 포함하지 않는다.
