# 체크메이트 개발 현황.

2026-09-25 첫 기반 개발을 시작했다. 로컬 폴더는 `C:/dev/E2E`로 유지한다. 설계는 [구현 기준](구현기준설계.md)과 [저장 및 연결 계약](저장및연결계약.md)을 따른다.

## 구현한 범위.

- Node.js 24·TypeScript·npm workspaces와 고정 의존성.
- Zod 결과 계약, 필수 검사·계획 연결·종료코드·소스·환경·증거·정리·확정 여부를 확인하는 판정.
- CLI 환경 진단과 결과 JSON의 읽기 전용 형식/판정 검사.
- 등록된 명령의 직접 자식 프로세스 실행, 실제 종료코드·시간 제한·취소·출력 상한·시작 실패 구분.
- Windows와 Linux의 빌드·자체 회귀를 실행하는 GitHub Actions 구성. Linux 시험은 엔진 기반의 이식성 확인이며 Linux 설치 앱 지원을 뜻하지 않는다.

현재 버전 표기는 `0.1.0-alpha.1`이며 배포 설치본을 만들거나 게시한 상태는 아니다. SQLite·실행 서비스·프로젝트 검사 접수·MCP·Electron UI·설치본은 아직 구현하지 않았다. 제목 검사 통과와 제품 기능 검증은 구분한다.

## 직접 확인하는 명령.

```powershell
npm ci --ignore-scripts
npm test
node packages/engine/dist/명령.js doctor --json
node packages/engine/dist/명령.js report validate '결과.json' --json
```

직접 실행한 Node 명령의 stdout에는 JSON 하나만 출력한다. `npm run checkmate -- doctor --json`도 사람이 사용할 수 있지만 npm 자체 안내가 앞에 붙으므로 프로그램 연동에는 직접 Node 명령을 사용한다.

`report validate`의 종료코드0은 파일의 형식과 판정 조건이 일치한다는 뜻이다. 파일이 실제 시험에서 생성됐다는 인증이나 대상 앱 통과를 뜻하지 않는다. 응답에 `evidenceAuthenticated: false`와 파일에 기록된 판정을 함께 표시한다. 실제 검사 명령의 완료/종료 규칙은 추후 run 명령에 적용한다.

## 검증과 제한.

Windows의 `npm test`에서 빌드와 실제 Node 자식/CLI를 포함한 회귀 시험을 통과했다. 거짓 통과, 누락, 소스 변경, 과거 결과, 중복·계획 밖 ID, 비영 종료, 시간 초과, 취소, 부모 환경 차단, 손상 JSON·UTF-8, 과대 파일, 출력 유출 경계를 검사한다. 테스트는 합성 자료와 자체 임시 파일만 사용하고 DB는 생성하거나 수정하지 않는다.

TypeScript의 Node 전역 타입은 engine 설정의 `types: ["node"]`로 명시했다. 한글 파일명의 외부 source map 경로 해석 경고는 inlineSourceMap·inlineSources 설정으로 해결했다. Context7에서 TypeScript 공식 자료를 확인한 뒤 적용했다. [types 설정](https://www.typescriptlang.org/tsconfig/types.html), [inlineSourceMap](https://www.typescriptlang.org/tsconfig/inlineSourceMap.html).

작업 실행기는 직접 자식의 종료만 확인한다. 손자 프로세스·Docker·서비스 장애 후 소유권 복구·앱 창 종료 후 지속 실행은 아직 제공하지 않는다. 다른 프로젝트 명령이나 실제 아틀리에 시험을 실행하지 않았다. HTTP 서버와 UI가 없는 단계이므로 접속 URL도 아직 없다.

다음 단계는 SQLite와 실행 서비스다. 관리 DB 초기화·기록 갱신·시험 DB 영향 계획을 구체화한 후 사용자 확인을 받아 구현 시험에 사용한다. 대상 PostgreSQL 쓰기 승인은 별도이며 과거 승인을 이전하지 않는다.
