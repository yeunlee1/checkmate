# 체크메이트 개발 현황.

2026-09-25 기준 `0.1.0-alpha.1` 개발판이다. 로컬 폴더는 `C:/dev/E2E`, 설계 기준은 [구현 기준 설계](구현기준설계.md)와 [저장 및 연결 계약](저장및연결계약.md)이다. 모델 API를 호출하지 않으며 사람용 앱·CLI와 AI용 stdio MCP를 제공한다.

## 구현과 사용.

프로젝트의 세 JSON 원본을 등록하고 프로필의 명령·쓰기 범위를 확인한 뒤 승인한다. 실제 소스 지문이 바뀌면 기존 승인을 재사용하지 않는다. 서비스는 별도 Node 작업 프로세스의 종료와 소스·환경·증거·정리를 확인한 뒤 SQLite에 최종 판정을 저장한다. 같은 작업 경로는 하나씩, 서로 다른 프로젝트는 최대 두 개를 실행한다.

Electron 화면에서 등록·계획·승인·실행·취소·이력·근거를 확인한다. CLI와 MCP도 같은 결과를 읽는다. MCP는 사람 전용 등록·승인·기준 활성화·복구·수동 정리 확인을 노출하지 않는다. 요약은 UTF-8 8KiB 이내이고 상세는 페이지로 나눈다. 민감한 증거는 메타데이터만 반환한다.

| 기능 | 현재 동작과 시험 |
|---|---|
| 요구사항 완료 근거 | 선택 검사, 누락, 범위 밖, 코드 경로와 증거를 연결한다. 이번 프로필 밖의 필수 항목을 완료로 표시하지 않는다. |
| AI 수정 자료 | 기대·관측·위치·증거 ID와 보완 지침을 묶는다. 긴 내용은 축약과 생략 개수를 표시한다. |
| 정보 노출 검사 | 합성 표식의 DOM 및 명시적 API 응답 노출을 역할 정책과 대조한다. 표식 자체는 해시로 바꾼다. |
| 실제 검출력 검사 | Stryker를 실행한 강한 검사는 10개 검출, 약한 검사는 6개 검출과 4개 생존을 기록했다. 합성 권한 함수 범위다. |
| 디자인 위반 위치 | 실제 브라우저 규칙·접근성 관측과 공개 PNG의 해시를 확인하고 일치하는 캡처에 위반 위치를 표시한다. |
| 미검증 보완 이력 | 같은 공백을 중복 기록하지 않고 실제 관련 검사 통과에만 보완 실행을 연결한다. 관측한 실패와 미검증을 구분한다. |
| 이력과 자료 | 과거 보고서는 원래 상태를 보존하되 현재 통과로 재사용하지 않는다. HTML 내보내기, 체크섬 백업, 새 빈 폴더 복구를 제공한다. |
| 중단 복구 | 중단된 실행을 미확인으로 보존한다. 사람이 정리를 확인한 감사 기록을 남겨 새 실행을 허용할 수 있으며 과거 판정은 바뀌지 않는다. |
| 설치 경로 | Forge와 Squirrel 개발 설치본 제작, 동봉 Node와 SQLite, 고정 사용자 CLI 연결, 설치 이벤트 처리를 구현했다. 공개 서명과 실제 설치 수용은 별도 조건이다. |

[사용 안내](사용안내.md), [검사 작성 안내](검사작성안내.md), [검출력 사용법](검출력사용법.md), [개발 설치본](개발설치본.md)을 따른다. `npm test`는 빌드·타입·회귀, `npm run desktop:test`는 실제 Electron 흐름을 검사한다.

## 검증 근거와 현재 진행.

2026-09-25 05:11 로컬 `npm test`에서 전체 빌드·타입 검사와 34파일 250개 시험이 통과했다. 환경별 시험 두 개는 건너뛰었고, 그중 포장 Node를 지정하는 설치 연결 시험은 별도 실행으로 통과했다. 합성 DB·실제 자식 프로세스·브라우저·CLI·MCP SDK의 연결을 검사한다.

확장 Electron 시험에서 등록부터 실제 실행과 결과, HTML 저장, 백업·복구, 가져온 이력, PNG 위반 위치가 통과했다. 검사한 1280/1920 화면과 100/150/200% 확대에서 가로 넘침과 자동 접근성 위반은 없었다. OS 파일 선택 결과는 시험용 경로로 고정했다.

첫 독립 검토의 비정상 종료 후 통과, 지문 제외 실행 경로, 긴 한글 요약 문제를 수정했다. 재검토에서 추가 발견한 `.env.*` 진입점의 승인 무효화 누락도 `19df2be`에서 수정하고 회귀를 추가했다. `26a1abe` 고정 커밋의 제품 경계와 설치 코드는 각각 독립 검토 중이다. 원격 Windows와 Linux 검사를 다시 실행 중이며 이 결과를 확인하기 전에는 develop 병합 완료로 표시하지 않는다.

앞선 기반 단계의 검토·병합은 [PR 2](https://github.com/yeunlee1/checkmate/pull/2), 현재 연결 개발은 [PR 3](https://github.com/yeunlee1/checkmate/pull/3)에서 추적한다. 초기 기반의 116개 시험과 현재 회귀를 합산하지 않는다.

## 남은 외부 조건.

아틀리에의 실제 PostgreSQL과 로그인·고객·견적 업무 검증은 대상 프로젝트의 격리 설정과 소유 자원 계약이 필요하다. [아틀리에 연결 안내](아틀리에연결안내.md)에 구체적인 변경 범위를 기록했다. 현재 합성 E2E와 과거 보고서 읽기를 실제 아틀리에 통과로 표시하지 않는다. 다른 프로젝트의 코드·DB·실행 중 서버를 변경하지 않았다.

개발 설치본은 제작했으나 최종 고정 커밋 재제작, 포장 앱의 반복 실행 수용, 깨끗한 Windows의 설치·제거·업데이트·복구와 코드 서명은 확인 중 또는 미실행이다. 서명 자격과 정식 릴리스 승인은 별도 입력이다. 자동 업데이트·Docker 자원 회수·악성 프로젝트 샌드박스를 제공한다고 주장하지 않는다.

체크메이트의 로컬 개발 DB 변경과 검증 후 develop 병합은 승인됐으며 main 병합·공개 릴리스·실제 자료 변경은 이번 범위에 포함하지 않는다.
