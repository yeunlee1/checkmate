# 아틀리에 검사 연결 안내.

## 독립 사본의 실제 DB와 업무 브라우저.

2026-09-25 체크메이트가 소유한 새 PostgreSQL과 실행별 시험 서버로 아틀리에 커밋 `6198da0436bed65072769898618f9690978d3827`의 독립 사본을 검사했다. 원본 폴더와 기존 서버·DB·환경 파일을 사용하지 않았다. 다음 결과는 그 사본과 해당 실행의 근거이며 원본 프로젝트의 이후 변경에 재사용하지 않는다.

| 프로필 | 실행 ID | 실제 결과 |
|---|---|---|
| PostgreSQL | `c0997805-1fd4-477f-b5dd-5531c3d07966` | Vitest 61개 중 60개 통과와 1개 건너뜀. 파일 단위 7개 통과와 1개 건너뜀으로 최종 `incomplete`. |
| 업무 브라우저 | `12ef11f4-9c3f-47ae-b130-a8d57291788c` | 실제 Chrome·Next·Nest·PostgreSQL의 업무 8단계와 최종 `passed`. |

두 실행은 동일한 소스 지문 `3ecdd6234b728b7dfdb2ac83bf5e2a7295bfabf51d719e75307e13fc60aedb84`를 사용했고 실행 전후에도 같았다. 실제 명령 종료 코드 0, 환경·증거·정리 검증과 컨테이너 부재를 확인했다. 제한 증거의 SHA256과 바이트 길이를 원본 파일과 대조했으며 브라우저가 소유한 자식 프로세스 3개도 종료됐다.

브라우저 흐름은 상태 확인, 사장 로그인, 직원 가입, 승인 전 고객 API 차단, 사장 승인 뒤 기존 직원 세션 접근, 고객 등록과 상세 조회, 견적 초안 저장, 새로고침 뒤 목록·상세·API 재조회다. 고객과 견적 API의 201, 견적 버전 1, 수량 2개와 단가 350000원에서 50000원을 할인한 합계 650000원을 확인했다. 가상 세션을 주입해 화면 로그인 성공을 대신하지 않았다.

PostgreSQL에서 건너뛴 1개는 기존 HTTP 시험의 Node 전용 연결 중단 검사를 Worker 분기에서 실행하지 않는 `it.runIf` 조건이다. 이 조건을 삭제하거나 통과로 바꾸지 않았다. 어댑터의 보고 유효성과 전체 검사 통과를 구분해 나머지 7개 파일의 통과를 보존하면서 필수 건너뜀을 `incomplete`로 남긴다. 실제 Vitest 실패·비정상 종료·파일 누락·개수 불일치는 실패 처리한다.

시험 사본에는 부모가 전달한 관리용 PG 연결만 받는 fixture, 구조화 결과 어댑터, 실제 환경 파일 자동 로딩을 거절하는 시험 서버, 동적 포트와 시험 캐시 경로를 준비했다. 초기 `.build/backend` 산출물과 Next의 `next-env.d.ts` 생성 때문에 소스가 달라진 첫 실행은 실패로 보존하고 새 계획으로 재실행했다. 다른 사본에 연결할 때도 필요한 사전 빌드와 타입 파일을 준비한 뒤 계획을 승인한다. 원본 아틀리에에 이 연결 파일을 자동 반영하지 않았다.

위 두 실행은 Windows 비밀 전달을 수정한 `2161815`의 재검증이다. 이전 `f308230f-dbad-46e9-8b51-ccaca77370a5`와 `b5a47fa8-ab4e-4953-87e1-d69f8f407765`의 소스·판정·증거에 대한 독립 검토도 통과했다. 설치된 앱과 동봉 Node의 실행 `514eee93-bdea-43e2-9efe-6efdd04549b6`에서도 화면의 등록·승인·실행을 거쳐 브라우저 8단계, 소스 동일과 자원 제거를 확인했다.

공개 저장소에는 대상 업무 소스와 시험 자료를 포함하지 않는다. 이 컴퓨터의 사본 위치는 `.runtime/아틀리에시험사본.json`, 실행별 결과와 파일 대조는 `.runtime/아틀리에실제수용-실행-<실행 ID>.json`에서 확인한다. 부모 자원의 복구 계약은 [격리 시험 DB](격리시험DB.md)에 있다.

## 확인한 실제 빠른 검사.

2026-09-25 아틀리에 커밋 `6198da0436bed65072769898618f9690978d3827`의 독립 시험 사본을 체크메이트에 등록하고 계획 확인·승인·실행·결과 조회를 수행했다. 원본 작업 폴더와 기존 DB·서버·잠금은 사용하지 않았다. 사본에 실제 환경 파일과 고객 자료를 복사하지 않았다.

체크메이트 실행 `9cc2780a-02d5-4b04-83a1-7cfc91c6a444`에서 기존 `npm run verify:quick`의 `format`, `types`, `runner`, `unit` 네 단계가 모두 통과했고 부모 명령 종료 코드 0을 관측했다. 엔진의 실행 전후 지문이 일치하며 최종 결과는 `finished`, `passed`, `finalized=true`, `integrity=verified`다. 원본 보고서와 단계 로그 등 증거 8개의 바이트 해시를 대조하고 제한 자료로 저장했다. 개별 Vitest 시험을 네 단계의 성공으로 대신 등록하지 않는다.

앞선 실행의 어댑터 서식 오류, 임시 Git 시험의 상위 저장소 탐색, 새 TypeScript 캐시에 따른 소스 변경은 각각 실패 이력에 보존했다. 사본 내부의 임시 디렉터리와 `GIT_CEILING_DIRECTORIES`를 지정하고 새 계획으로 실행했다. 사용한 Node·npm 경로와 버전, 고정 환경 변수, 캐시 쓰기 범위를 계획에 기록했다. 이 검사는 격리 PostgreSQL·브라우저·두 서비스 빌드를 포함하지 않는다.

## 확인한 현재 형식.

아틀리에 노트의 `package.json`은 `npm run verify:quick`을 `node scripts/verify.mjs quick`에 연결한다. `scripts/verify.mjs`의 빠른 검사는 `format:check` → `typecheck` → `node --test tests/verification/runner.node.mjs` → `npm test -- tests/unit tests/config.test.ts` 순서다. 앞 단계가 실패하면 나머지는 `not-run`이다. 실행 시 `.runtime/verification/active.lock`을 만들고 시각과 PID로 정한 `.runtime/verification/<실행>/`에 `report.json`, 실행한 단계의 `<id>.log`, 최종 저장이 완료되면 `summary.txt`를 쓴다. `report.json`의 `checks-passed`는 중간 상태다. 최종 `passed`와 실제 명령 종료코드 `0`을 함께 관측해야 현재 실행의 성공을 말할 수 있다.

현재 소스에서 도출한 축약 형식은 아래와 같다. 지문과 값은 가상 예시이며 실제 고객 자료가 아니다.

```json
{
  "mode": "quick",
  "status": "passed",
  "source": { "commit": "bbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbb", "fingerprint": "aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa", "files": 4 },
  "sourceAfter": { "commit": "bbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbb", "fingerprint": "aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa", "files": 4 },
  "omitted": ["격리 DB 통합 검사", "두 서비스 빌드", "실제 브라우저 검사"],
  "steps": [
    { "id": "format", "status": "passed", "exitCode": 0, "log": "format.log" },
    { "id": "types", "status": "passed", "exitCode": 0, "log": "types.log" },
    { "id": "runner", "status": "passed", "exitCode": 0, "log": "runner.log" },
    { "id": "unit", "status": "passed", "exitCode": 0, "log": "unit.log" }
  ]
}
```

최상위 `report.json`에는 실제 부모 명령의 종료코드가 없다. `steps`도 개별 Vitest 시험의 판정을 담지 않는다. 따라서 과거 JSON만 받아 읽는 `importAtelierReport(input: unknown)`은 원문 상태를 `reportedStatus`로 남기고 `origin: 'imported'`, `reusablePassed: false`, `effectiveVerdict: 'unknown'`을 고정한다. 문자열 또는 Buffer를 넘기면 `originalSha256`은 그 원본 바이트의 SHA-256이다. 이미 파싱한 객체를 넘기면 현재 `JSON.stringify` 직렬화의 SHA-256이므로 원래 파일 바이트 지문이 필요할 때는 원본 Buffer를 넘겨야 한다. 오류는 `{ ok: false, errors: [{ code, path }] }`이며 원문 로그, 단계 인자, 라벨, 고객명, 토큰, 절대경로를 되돌리지 않는다. 개별 시험 결과가 없으면 단계 `passed`를 개별 시험 `passed`로 확장하지 않는다.

환경의 `kind`는 현재 소스에서 확인한 단계 계약의 단서다. 고객·견적·상품·세트 브라우저 단계는 로컬 D1을 사용하고, `staff-ui`는 4318번 정적 화면과 모의 API를 사용한다. 함께 있거나 다른 단계만 있으면 보고서 수준은 `unknown`이다. 모든 가져온 결과의 `environment.verified`는 `false`다. 현재 과거 보고서에는 PostgreSQL을 실제로 사용했다는 구조화 근거가 없어 PostgreSQL로 분류하지 않는다. 이름만 보고 현재 실행 환경을 인증하지 않는다.

## 빠른 검사 실행을 연결할 때.

체크메이트의 실행 서비스가 먼저 실행별 `runId`와 소유 범위를 기록하고 대상 프로젝트의 검증 명령을 자식 프로세스로 시작해야 한다. 작업 폴더는 아틀리에 프로젝트 루트, 인자는 `npm run verify:quick`이다. 외부 `node`와 `npm`의 설치 위치와 실제 버전을 탐색하고, `npm_execpath`가 npm에서 제공되는지 확인해야 한다. `scripts/verify.mjs`는 직접 `node scripts/verify.mjs quick`으로 시작하면 `npm_execpath` 부재를 거절하며, 하위 단계는 `process.execPath`로 실행한다. 설치된 Node와 npm이 체크메이트의 내장 또는 선택 Node와 다를 수 있으므로 발견한 경로와 버전을 실행 전 확인해야 한다. 아틀리에의 `package.json`과 `node_modules` 준비도 별도 검사 대상이다.

실행 중 대상 소스가 바뀌면 아틀리에 러너가 `source-changed`를 쓸 수 있다. 잠금이 있으면 소유 프로세스를 확인해야 하며 다른 세션의 `active.lock`을 지우지 않는다. 체크메이트가 부모 프로세스 종료코드, 보고서 최종 저장, 전후 소스 지문, 로그와 정리 결과를 같은 `runId`로 대조한 뒤에만 새 실행을 판정해야 한다. 위의 실제 빠른 검사에서는 이 경로를 확인했으며 다른 사본이나 이후 변경에 같은 통과를 재사용하지 않는다.

## 원본 프로젝트에 연결을 옮길 때의 계약.

- 원본 `tests/postgres/database.ts`의 독립 실행과 체크메이트 관리 실행을 구분한다. 관리 실행에서는 체크메이트 부모가 생성 전 의도와 정확한 컨테이너 ID를 기록하고 최종 정리를 담당한다. 어댑터는 부모가 전달한 해당 컨테이너 안에서만 호출별 DB와 합성 자료를 만들며 관리 연결이 없거나 잘못됐을 때 기존 DB나 자체 Docker 실행으로 후퇴하지 않는다.
- M2의 기존 업무 브라우저 스크립트는 고정 3000번 화면, 4000번 API, 공용 영속 D1 경로와 현재 서버를 사용한다. `scripts/verify-preflight.mjs`도 이 주소와 설치된 Chrome을 검사한다. 현재 PostgreSQL 서버를 실행하는 `scripts/start-postgres-backend.mjs`는 `backend/.env.postgres.local`을 읽고 `backend/.env.local`을 Wrangler에 넘긴다. 대상 담당자는 실제 환경 파일의 자동 로딩을 차단한 시험 전용 설정, 실행별 포트, 인증 Origin 일치, 독립 빌드 경로, 격리 PG, 개별 시험 결과와 증거를 내는 reporter를 준비해야 한다.
- 준비 전에는 현재 3000/4000 서버, 실제 DB, 기존 잠금을 재사용하거나 종료하지 않는다. 위의 실제 수용은 승인된 체크메이트 시험 사본에서 수행했으며 원본 프로젝트 변경이나 운영 자료 변경 승인을 뜻하지 않는다.

근거는 아틀리에 노트의 `scripts/verify.mjs`, `tests/verification/runner.node.mjs`, `tests/postgres/database.ts`, `tests/e2e/first-workflow.mjs`, `tests/e2e/staff-workflow.mjs`, `scripts/verify-preflight.mjs`, `scripts/start-postgres-backend.mjs`, `package.json`의 현재 소스다.
