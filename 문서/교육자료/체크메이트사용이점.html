사람과 AI가 함께 쓰는 검증 도구

만드는 속도만큼,
확인도 따라오도록.

AI가 코드를 고칠 때마다 같은 화면을 눌러 보고, 긴 로그를 읽고, 빠뜨린 검사가 없는지 확인하고 있나요?

체크메이트는 준비한 검사를 반복 실행하고, 결과와 근거를 모아 주는 데스크톱 프로그램입니다. 사람과 AI가 다음에 무엇을 확인하고 고칠지 판단하도록 돕습니다.

검사를 시작했다는 사실과, 실제로 통과했다는 결과를 구분합니다.

이 프로그램이 필요한 이유

반복 확인은 검사로 옮기고, 사람은 실패 원인과 중요한 판단에 집중할 수 있습니다.

01

개발 후의 일이 달라집니다.

“고쳤어요” 다음에 할 일.

예를 들어 주문 저장 화면을 수정했다고 해 봅시다. 자주 확인하는 동작을 검사로 연결해 두면, 다음 수정 때 같은 기준으로 다시 확인할 수 있습니다.

검증을 따로 연결하지 않은 경우

확인할 일이 사람에게 모입니다.

  1. 직접 눌러 보기저장, 재조회, 모바일 화면을 다시 확인합니다.
  2. 문제를 설명하기로그와 화면을 모아 AI에 전달합니다.
  3. 수정 후 다시 확인하기놓친 조건이 없는지 기억을 되짚습니다.

체크메이트에 검사를 연결한 경우

같은 기준과 기록으로 이어갑니다.

  1. 준비한 검사를 다시 실행현재 코드의 실행 계획을 확인하고 승인합니다.
  2. 실패와 근거를 함께 조회AI는 기대값, 실제 결과, 관련 위치를 읽습니다.
  3. 보완할 항목을 확인하고 재검사검사하지 못한 부분도 확인 목록에 남깁니다.

이미 Playwright나 다른 자동 테스트를 쓰고 있어도 활용할 수 있습니다. 기존 검사 코드를 등록된 Node 명령과 결과 형식에 연결하는 작업은 필요합니다.

02

다섯 가지 사용 이점

어떤 수고가 줄어들까요?

검사 실행뿐 아니라 결과를 해석하고, AI에게 전달하고, 다음 수정까지 이어 가는 과정에 도움이 됩니다.

01

같은 동작을 매번 눌러 보던 수고.

저장, 계산, 화면 표시처럼 반복해서 확인하는 동작을 검사로 준비해 두면 수정할 때마다 재사용할 수 있습니다.

어떻게 가능한가요?프로젝트별 검사와 실행 묶음을 등록하고, 승인된 계획의 명령을 실제 프로세스에서 실행합니다. 테스트가 없는 동작은 먼저 검사를 작성해야 합니다.

02

AI의 완료 보고를 다시 확인하던 수고.

실제로 무엇이 실행됐고 무엇이 확인됐는지 근거를 볼 수 있습니다. 근거가 부족한 부분을 찾아 추가 확인하기 쉬워집니다.

어떻게 가능한가요?필수 검사, 프로세스 종료, 소스 변경 여부, 환경, 증거, 정리와 결과 확정을 함께 확인합니다. 최종 통과는 해당 실행 범위의 판정입니다.

03

긴 로그를 통째로 전달하던 수고.

AI가 결과 요약부터 읽고, 필요한 실패 근거만 더 조회하도록 할 수 있습니다. 대화에 넣는 불필요한 정보를 줄이는 데 도움이 됩니다.

어떻게 가능한가요?작은 요약, 페이지별 상세, 수정에 필요한 자료 묶음을 제공합니다. 토큰 절감률을 측정한 기능은 아니며 실제 효과는 조회 방식에 따라 달라집니다.

04

검사하지 않은 부분을 기억하던 수고.

요구사항에 연결된 검사와 빠진 근거를 확인해 다음 보완 작업으로 이어 갈 수 있습니다. 선택한 검사 밖의 요구사항도 구분합니다.

어떻게 가능한가요?등록된 요구사항과 검사 결과를 대조해 누락, 범위 밖, 근거 부족을 기록합니다. 등록하지 않은 요구사항까지 자동으로 발견하는 것은 아닙니다.

05

사람과 AI 사이에서 결과를 옮기던 수고.

사람은 앱에서, AI는 CLI나 MCP로 같은 실행을 확인할 수 있습니다. 실행 이력이 남아 다음 대화에서도 결과를 찾아볼 수 있습니다.

어떻게 가능한가요?같은 자료 폴더에 연결된 앱·CLI·MCP가 실행 ID와 저장된 결과를 공유합니다. AI 클라이언트의 연결 설정은 별도로 준비합니다.

03

내 작업에 대입해 보기

이럴 때 쓸 수 있습니다.

아래는 필요한 검사 코드와 기대값을 미리 연결했다고 가정한 설명용 예시입니다. 버튼은 설명을 바꾸며 실제 검사나 DB 작업을 실행하지 않습니다.

화면 수정 예시를 보고 있습니다.

활용 예시 01 · 프론트엔드

화면을 고쳤는데 저장 버튼이 밀렸다면.

준비해 둔 기준

휴대전화 크기의 화면에서도 저장 버튼이 화면 안에 보여야 합니다.

검사에서 읽는 근거

브라우저가 관측한 버튼 위치와 화면 크기, 연결된 캡처를 확인합니다.

사람과 AI가 할 일

AI는 관련 레이아웃을 고치고 재검사합니다. 사람은 화면 의도와 사용감을 확인합니다.

도움이 되는 점. 문제가 생긴 위치와 검사 조건을 다시 설명하는 부담이 줄어듭니다.

위치·접근성처럼 명시한 규칙을 확인합니다. 디자인의 아름다움이나 모든 사용성을 자동 판정하지는 않습니다. 관측 오류는 실패 내용과 원본 근거를 함께 확인해야 합니다.

활용 예시 02 · 백엔드

할인 계산을 고쳤는데 저장값이 다르다면.

준비해 둔 기준

합성 주문의 예상 금액과 저장 후 다시 읽은 금액이 같아야 합니다.

검사에서 읽는 근거

검사 코드가 비교한 기대값과 실제 계산·재조회 값, 관련 코드 위치를 확인합니다.

사람과 AI가 할 일

AI는 계산 또는 저장 코드를 고칩니다. 사람은 할인과 반올림 규칙이 맞는지 판단합니다.

도움이 되는 점. 저장 메시지만 보고 끝내지 않고, 실제 값이 맞는지 같은 조건으로 다시 확인할 수 있습니다.

계산 규칙과 검사용 자료·환경은 프로젝트에서 준비합니다. 체크메이트가 업무 규칙을 추론해 정답을 만드는 기능은 없습니다.

활용 예시 03 · 보안과 권한

일반 직원 화면에 관리자 정보가 보인다면.

준비해 둔 기준

직원 역할에서는 지정한 관리자용 합성 표식이 화면이나 검사 대상 API 응답에 없어야 합니다.

검사에서 읽는 근거

역할별 정책과 실제 노출 관측을 대조합니다. 표식 원문은 해시로 바꾸어 기록합니다.

사람과 AI가 할 일

AI는 해당 노출 경로를 고칩니다. 사람은 역할 정책을 검토하고 추가 권한 검사를 연결합니다.

도움이 되는 점. 사람이 매번 역할을 바꾸며 찾던 특정 정보 노출을 반복해서 검사할 수 있습니다.

지정한 표식·경로·역할의 검사입니다. 모든 취약점, 권한 우회, 실제 접근 거부를 보장하지 않습니다. 접근 성공·거부와 다른 보안 조건은 별도 검사로 연결합니다.

AI에게는 요약부터,
필요한 근거는 그다음에.

처음부터 로그 전체를 대화에 붙여 넣을 필요가 줄어듭니다. AI는 실패한 항목과 누락된 근거를 보고, 필요한 상세만 요청할 수 있습니다.

04

AI와 함께 쓰는 방법

개발과 재검사를 연결합니다.

AI는 코드를 만들고 고칩니다. 체크메이트는 연결한 검사를 실행하고 근거를 제공합니다. 사람은 실행 계획과 중요한 판단을 확인합니다.

  1. AI와 개발자

    코드·검사 준비

    기능을 구현하고 확인할 조건을 검사 코드에 담습니다.

  2. 사람

    현재 계획 승인

    실행할 명령과 쓰기 범위를 확인하고 승인합니다.

  3. 체크메이트

    실제 검사 실행

    선택한 검사를 실행하고 종료와 근거를 확인합니다.

  4. AI와 사람

    실패·공백 확인

    요약을 읽고 실패 이유와 근거 부족을 살펴봅니다.

  5. AI와 개발자

    수정 후 재검사

    코드와 검사를 보완하고 새 계획 확인으로 돌아갑니다.

소스나 검사 기준이 바뀌면 계획과 승인도 다시 확인합니다. MCP에는 사람이 할 승인을 AI가 대신하는 도구가 없습니다.

“수정한 기능을 체크메이트로 검사해 줘.
실패 근거와 아직 확인하지 못한 항목도 같이 알려 줘.”

프로젝트·검사·MCP 연결을 준비한 뒤 AI에게 요청하는 예시입니다. 새 승인이 필요하면 사람에게 요청하도록 합니다.
05

도입 판단

반복할 일이 많을수록 도움이 됩니다.

처음 연결하는 데에는 작업이 필요합니다. 자주 바뀌고, 같은 확인을 되풀이하는 프로젝트부터 적용하는 것이 좋습니다.

이런 상황이라면 잘 맞습니다.

  • AI가 자주 코드를 수정합니다.

    개발 속도에 비해 사람이 다시 확인하는 시간이 많이 듭니다.

  • 되풀이하는 검사 조건이 있습니다.

    저장, 계산, 권한, 화면 크기처럼 결과를 비교할 수 있습니다.

  • 여러 대화에서 같은 프로젝트를 이어 갑니다.

    어떤 코드와 조건에서 검사했는지 기록을 다시 찾고 싶습니다.

이 부분은 준비하고 판단해야 합니다.

  • 검사 코드와 기대값.

    검사를 연결하고 유지하는 일이 필요합니다. 폴더만 등록해서 모든 기능을 검사할 수는 없습니다.

  • 새 계획 승인과 미검증 보완.

    코드가 바뀌면 계획을 다시 확인합니다. 빠진 검사는 사람이나 외부 AI가 작성하고 연결합니다.

  • 업무·디자인 의도와 최종 판단.

    테스트 자체가 틀릴 수 있습니다. 중요한 흐름의 실제 사용성과 검사 기준의 적절성은 사람이 검토합니다.

현재 상태. 이 자료는 0.1.0-alpha.1 개발판 기준입니다. 체크메이트는 모델 API를 직접 호출하지 않으며, 연결한 외부 AI의 계정과 사용량 제한은 그대로 적용됩니다. 앱 안에 AI 채팅이나 자동 코드 수정 기능이 들어 있는 것은 아닙니다.

통과는 선택한 검사와 확인된 근거의 범위를 뜻합니다. 악성 프로젝트를 격리하는 샌드박스는 제공하지 않습니다. 코드 서명, 깨끗한 Windows 장비의 설치 수용, 버전 간 업데이트 검증 등 정식 출시 조건은 남아 있습니다.

06 / 처음 시작한다면

가장 자주 확인하는
동작 하나부터.

모든 검사를 한꺼번에 옮길 필요는 없습니다. 반복되는 확인 하나를 연결하고, 실제로 문제가 생겼을 때 찾고 고치는 데 도움이 되는지 살펴보세요.

상세 사용 설명서전체 구조 이해하기

설명서 링크를 이용하려면 저장소의 폴더 구성을 유지하세요. 이 소개 자료 자체는 파일 하나로 인터넷 없이 읽을 수 있습니다.

  1. 예제로 결과 읽는 법을 익힙니다.

    대표 합성 예제의 정상 검사와 의도적 결함 검사를 실행해 결과와 근거를 비교합니다.

  2. 내 프로젝트의 검사 하나를 연결합니다.

    예를 들어 저장 후 재조회 검사를 만들고, 기대값과 근거를 남깁니다.
