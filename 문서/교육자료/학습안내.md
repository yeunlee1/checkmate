# 체크메이트를 이해하는 학습 순서.

먼저 [체크메이트 이해하기](체크메이트이해하기.html)를 브라우저로 연다. 인터넷 연결 없이 그림·판정 실험·퀴즈·코드 검색을 사용할 수 있다. GitHub에서 HTML 원문이 보이면 저장소를 내려받고 이 파일을 직접 연다.

체크메이트를 처음 보는 사람이 전체 구조를 이해한 뒤 실제 코드까지 찾아갈 수 있도록 구성했다. 버튼 사용법은 [상세 사용 설명서](../상세사용설명서.md)를 함께 참고한다. 설명서로 이동하려면 저장소의 문서 폴더 구성을 유지한다.

## 도착 목표.

학습을 마치면 다음 질문에 자기 말로 답할 수 있어야 한다.

- 체크메이트, 검사 대상 프로그램, AI는 각각 무슨 일을 하는가?
- 데스크톱 화면, CLI, MCP는 어디서 만나고 어디서 역할이 갈리는가?
- 프로젝트 등록, 실행 계획, 사람의 승인, 실제 실행은 왜 나뉘어 있는가?
- 검사 명령이 끝난 것과 최종 통과는 왜 다른가?
- 검사 정의나 프로그램 코드가 바뀌면 무엇을 다시 확인해야 하는가?
- 새 검사를 추가하거나 문제를 조사할 때 어느 파일부터 읽어야 하는가?

## 여섯 장면으로 배우기.

| 장면 | 먼저 이해할 질문 | 손으로 확인할 일 |
| --- | --- | --- |
| 1. 세 주인공 | AI가 검사했다고 말하면 끝인가? | 사람·AI·체크메이트·대상 프로그램의 역할을 구분한다. |
| 2. 세 개의 입구 | 화면과 터미널과 MCP가 다른 프로그램인가? | 같은 검사 서비스에 도달하는 길을 따라간다. |
| 3. 실행 전 약속 | 등록했는데 바로 실행하지 않는 이유는? | 검사 정의에서 계획과 승인으로 이어지는 자료를 읽는다. |
| 4. 검사 한 번의 여정 | 실행 버튼 뒤에서는 무슨 일이 일어나는가? | 접수·작업·관측·증거·저장 순서를 따라간다. |
| 5. 결과를 믿는 조건 | 종료 코드 0이면 통과인가? | 조건을 바꾸며 통과·실패·미완료·미확인을 비교한다. |
| 6. 고치고 다시 확인하기 | 실패를 발견한 뒤 어디를 고쳐야 하는가? | 앱 문제와 대상 프로젝트 문제를 나누고 다음 읽을 파일을 찾는다. |

각 장면은 쉬운 설명, 그림, 작은 조작, 실제 코드 근거 순서로 읽는다. 코드 근거는 필요할 때 펼쳐 본다. 비유와 실제 구현은 구분해서 표시한다.

## 두 번째 읽기.

첫 번째에는 전체 흐름을 이해한다. 두 번째에는 관심 있는 장면의 실제 파일과 함수를 연다. 언더스탠드 지도는 그 뒤에 연결된 파일을 더 찾아보는 도구로 사용한다.

학습용 모형의 버튼은 이해를 위한 상태만 바꾼다. 실제 프로젝트를 등록하거나 검사·DB 작업을 실행하지 않는다. 실제 실습은 사용 설명서의 대표 합성 예제를 사용한다.

## 자료의 근거.

분석 기준은 `1ecf77b819a772398c457fc6f5201fa88331edfd`다. 언더스탠드 분석 결과와 실제 소스를 대조했으며, 코드 발췌 18곳의 원문·줄 번호·파일 해시·GitHub 링크는 [학습 근거](학습근거.json)에 기록한다. 원문 링크는 이 커밋에 고정된다.

- [언더스탠드 지도](../../.ua/knowledge-graph.json)는 파일과 주요 함수·클래스의 역할 및 관계를 담는다.
- [분석 제외 설정](../../.ua/.understandignore)은 사용자가 승인한 범위다. 실행 자료·실제 DB·비밀 설정·빌드 결과·이미지·생성 HTML·교육자료 자체를 제외한다.
- 지도는 정적 분석 결과다. 모든 함수 호출 경로나 모든 실행 성공을 증명하지 않는다. 오래된 설계 문서는 그 문서의 설명이며 현재 기능 구현의 증거로 대신하지 않는다.
- 판정 실험은 실제 `assessResult`의 TypeScript 원문을 JavaScript로 변환해 HTML에 포함한다. 변환에는 저장소에 설치된 esbuild의 [TypeScript 로더](https://esbuild.github.io/content-types/#typescript)를 사용한다. 다른 조작은 설명용이며 프로젝트 실행·승인·DB 작업을 하지 않는다.

## 다시 만들고 확인하기.

이미 생성된 HTML을 읽는 데 Node나 플러그인 설치는 필요하지 않다. 수정·재생성할 때는 저장소의 개발 의존성과 빌드된 계약 패키지가 필요하다. 화면 검증에는 Playwright Chromium도 필요하다. 없는 환경에서는 `npx playwright install chromium`으로 준비한다.

```powershell
node 문서/교육자료/교육자료생성.mjs
node 문서/교육자료/교육자료검증.mjs
```

생성기는 코드 근거 파일이 지도 기준 커밋과 다르면 멈춘다. 앱 소스를 수정한 뒤에는 Understand Anything 분석과 교육 설명을 함께 갱신한다. 지도 자동 갱신은 켜지 않았다.

검증기는 코드 원문과 해시, 실제 판정 함수와의 비교, 화면 너비 다섯 가지, 접근성, 키보드, 퀴즈, 파일 연결 탐색, 오프라인, JavaScript 비활성 상태, 인쇄용 펼치기 동작을 확인한다. 결과와 캡처는 `.runtime/검증/교육자료/`에 남긴다. 이 검사는 교육 산출물의 검증이며 앱 전체·설치본·실제 대상 프로젝트의 E2E 검증과 구분한다.

## 분석에서 확인한 범위와 한계.

승인한 인벤토리 168개 파일을 모두 포함했다. 코드 118개, 설정 15개, 문서 27개, 인프라 2개, 마크업 4개, 스크립트 2개다. 직접 데이터 파일로 분류된 항목은 없다. DB 스키마 코드는 분석했지만 실제 DB 내용은 읽지 않았다.

공식 구조 추출기가 내부 구조를 건너뛴 파일 11개는 원문을 읽어 보완했다. HTML·CSS 4개, Git 속성·훅 3개, 글꼴 라이선스 1개, preload의 CTS 1개, PowerShell 2개다. 일부 클래스 메서드는 개별 줄 범위가 없고 익명 CLI·IPC 콜백도 별도 노드로 나누지 않았다. 해당 동작은 교육자료의 실제 원문에서 읽는다.

독립 검토에서 SQLite 초기화와 실행기의 결과 후보 반환을 설명한 요약 세 곳을 실제 코드에 맞게 바로잡았다. 합성 시험용 앱에 붙었던 부적절한 `tested_by` 관계 한 개는 복원하지 않았다. 추출기가 해결한 내부 가져오기 관계 209개를 지도와 대조했다. 이것이 작업공간 패키지 식별자로 연결된 모든 관계까지 망라한다는 뜻은 아니다. `tested` 표식 역시 시험 실행·통과 증명이 아니다.

최종 지도에는 노드 387개와 연결 754개가 있다. 노드 유형은 파일 124개, 함수 194개, 클래스 23개, 파이프라인 4개, 문서 27개, 설정 15개다. 같은 워크플로의 파일과 내부 작업을 구분한 노드 두 개가 있어 파일 수준 노드 수와 고유 파일 수는 다르다. 연결 유형은 `contains` 250개, `exports` 84개, `imports` 209개, `tested_by` 113개, `calls` 40개, `related` 50개, `configures` 8개다.

책임 영역은 제품과 사용 문서, 공유 검사 계약, 프로젝트와 제품 서비스, 로컬 기록과 복구, 검사 실행과 증거, 로컬 접속과 진입, 데스크톱 화면, 합성 검증 예제, 회귀 검증, 빌드와 개발 자동화의 10개다. 언더스탠드 지도 자체에는 12단계 안내가 있고, 이 교육 화면은 이를 여섯 장면의 학습 흐름으로 엮었다.

공식 구조 검증과 스키마 검증에서 오류는 없었다. 다만 연결이 잡히지 않은 노드 19개가 경고로 남았다. 문서·설정·훅과 일부 계약 파일을 포함하며, 파일이 누락됐거나 실제로 사용되지 않는다는 의미는 아니다. 근거 없는 연결을 만들어 경고를 없애지 않았다. 구조 지문 기준은 전체 168개 파일에 생성했다.

분석한 168개 파일 전체를 기준 커밋과 줄바꿈을 정규화해 대조했고 내용 변경이 없었다. 대시보드의 Git 변경 경고에는 분석 범위에서 제외한 교육자료 추가도 포함될 수 있다. 이 경우 경고의 파일 목록과 분석 제외 설정을 함께 확인한다. 지도 기준 커밋을 실제 분석 없이 최신 값으로 바꾸지 않는다.

## 교육자료 검증 결과.

2026-09-25에 생성과 검증 명령이 종료 코드 0으로 끝났다.

- 코드 발췌 18곳의 현재 원문·줄 범위·파일 해시와 분석 지도 연결을 확인했다.
- 원본 판정 함수와 브라우저의 함수가 합성 입력 504개에서 같은 결과를 냈다.
- 1440·1180·768·390·320px에서 가로 넘침과 자동 접근성 검사 위반이 없었다. 데스크톱·모바일 캡처도 직접 확인했다.
- 입구 선택, 여정 이동, 목차 표시, 퀴즈, 키보드 펼치기, 파일 검색과 가져오기 관계 탐색이 통과했다.
- 오프라인에서 외부 요청과 페이지 오류가 없었다. JavaScript를 끈 상태에서도 본문과 원문 펼치기를 확인했다.
- 인쇄 미디어의 목차 숨김과 코드 펼치기·복원을 확인했다. 실제 종이 인쇄 및 PDF 전체 페이지 검수는 수행하지 않았다.
- 관련 `tests/판정.test.ts` 25개와 한국어 Git 제목 검사를 통과했다. 설명과 핵심 소스의 독립 검토에서 발견한 두 문제를 수정하고 재확인했으며 남은 차단 이슈는 없었다.

지도 미리보기는 고정 버전의 사전 빌드 다운로드가 404를 반환해 설치된 대시보드를 사용하는 방식으로 전환했다. 교육용 HTML 자체는 이 서버나 플러그인 없이도 읽을 수 있다.
