# 테스트 검출력 검사.

## 범위와 입력.

`adaptStrykerReport(report, scope, exclusions?)`는 Stryker 10.0.0 JSON 보고서를 읽어 CheckMate 결과로 정규화한다. `report`는 JSON 파싱 결과이고, `scope`는 `{ id: string, files: readonly string[] }`이다. `files`는 보고서 `files`의 상대 경로 키와 정확히 일치해야 한다. 실행과 대상 프로젝트 변경은 이 함수가 담당하지 않는다.

```ts
const result = adaptStrykerReport(report, {
  id: '권한 계산 검사',
  files: ['계산.mjs'],
});
```

반환값에는 `status`, `scope`, `schemaVersion`, `findings`, `counts`, `score`, `reason`이 있다. 각 변이의 `file`, `id`, `mutatorName`, `location.start/end.line/column`, Stryker 원래 `status`, 수동 `exclusion`을 확인할 수 있다. 위치의 줄과 열은 1부터 시작하며 끝 위치는 제외된다. 원본 `source`, `replacement`, `statusReason`, 시험 실패 메시지, 프로젝트 절대 경로는 반환하지 않는다.

보고서의 필수 구조, 지원 스키마 버전, 상태, 위치, 범위, 중복 식별자를 검사한다. 필수 값이 잘못되거나 범위 안에 변이가 하나도 없으면 `unverified`와 `score: null`을 반환한다. 알 수 없는 상태를 검출 성공으로 간주하지 않는다.

## 판정과 점수.

| Stryker 상태 | 결과의 의미 | 점수 처리 |
| --- | --- | --- |
| `Killed` | 시험 실패로 변이 검출 | 분자와 분모에 포함 |
| `Timeout` | 실행 시간 초과 | Stryker 정의에 따라 분자와 분모에 포함하되 통과 판정은 보류 |
| `Survived` | 시험이 변이를 놓침 | 분모에 포함하고 `failed` |
| `NoCoverage` | 해당 변이를 실행한 시험이 없음 | 분모에 포함하고 `failed` |
| `CompileError`, `RuntimeError` | 변이 실행 오류 | 점수에서 제외하고 `unverified` |
| `Ignored`, `Pending` | 무시 또는 미실행 | 점수에서 제외하고 `unverified` |

점수는 `score.detected / score.denominator × 100`이다. `detected`는 `Killed + Timeout`, 분모는 수동 제외하지 않은 `Killed + Timeout + Survived + NoCoverage`다. 변이 상태별 개수는 `counts`에 원래 상태대로 남는다. 시간 초과는 점수 계산에서 검출로 분류되지만 `Killed` 개수로 합치지 않으며, 이것만으로 CheckMate 검사를 통과시키지 않는다. 오류나 미실행이 있으면 점수가 100이어도 판정은 `unverified`다. 생존 또는 미적용 변이가 있으면 판정은 `failed`다.

동등 변이는 자동 추정하지 않는다. 사람이 파일, 변이 ID, `kind: 'equivalent'`, 비어 있지 않은 `reason`을 지정한 `Survived` 또는 `NoCoverage` 변이만 별도 제외한다. Stryker의 `Ignored`는 사람이 `kind: 'excluded'`와 사유를 지정했을 때만 승인된 제외로 취급한다. 수동 제외 후 점수는 선택한 검증 범위의 조정 점수이므로 원본 Stryker 점수와 다를 수 있다. 제외한 변이도 `findings`와 원래 상태별 `counts`에 남고 `counts.excluded`에 별도 집계된다.

## 실제 합성 실행 검증.

루트 개발 의존성에 `@stryker-mutator/core@10.0.0`과 `@stryker-mutator/vitest-runner@10.0.0`이 설치된 뒤 다음 명령을 실행한다.

```powershell
npx vitest run tests/검출력검사.test.ts
node scripts/검출력검증.mjs
npm run typecheck
```

스크립트는 `.runtime/검증/검출력/<uuid>`에만 합성 권한 함수, 강한 검사, 약한 검사와 설정을 만든다. 각 하위 폴더에서 `node <루트>/node_modules/@stryker-mutator/core/bin/stryker.js run stryker.config.json`을 실행한다. Stryker의 임시 폴더, Vitest 캐시, JSON 보고서와 프로세스 임시 파일은 그 실행 폴더 안에 둔다. 종료 후 소유 경로를 확인해 자신이 만든 UUID 폴더만 지우고 삭제 여부를 다시 확인한다.

2026-09-25 로컬 합성 실행에서 강한 검사는 `Killed 10`, `Survived 0`, `Timeout 0`이었고 약한 검사는 `Killed 6`, `Survived 4`, `Timeout 0`이었다. 이는 작은 합성 권한 함수의 검출력 차이만 보여준다. 대상 프로젝트의 실제 검사, 전체 앱 회귀, 운영 자료 또는 설치본 검증 결과는 아니다.
