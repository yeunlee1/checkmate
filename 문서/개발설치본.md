# Windows 개발 설치본

이 문서는 로컬에서 서명 없는 Windows x64 개발 설치본을 만드는 절차다. 제품 소스 전체 빌드와 시험은 총괄 작업에서 먼저 통과해야 한다. 설치본 제작 스크립트는 현재 `packages/*/dist`를 입력으로 사용하며 소스를 다시 빌드하지 않는다.

## 준비와 실행

Node 24.18.0 x64, npm, Forge 7.11.2, Squirrel maker 7.11.2, esbuild 0.28.2가 필요하다. `packages/engine/native/작업보호.exe`와 `node_modules/better-sqlite3/prebuilds/win32-x64.node`가 준비되어 있어야 한다. 후자는 동봉 Node 24.18.0에서 실제 SQLite 메모리 질의로 다시 확인한다.

```powershell
node scripts/개발설치본.mjs
```

매 실행은 `.runtime/개발설치본/<uuid>`에 새 독립 폴더를 만든다. 기존 폴더를 삭제하거나 덮어쓰지 않는다. `제작보고서.json`에 Git 커밋, 시작 및 종료 시 작업 트리 변경 여부, 제작 입력 파일의 SHA256 지문, 동봉 Node의 공식 SHA256, ABI 시험, 포장 경로, 생성물 경로와 SHA256을 기록한다. 실패하면 같은 보고서에 오류를 남긴다.

## 포함 범위

`app`에는 `checkmate` 패키지 정보, esbuild로 묶은 Electron main, 기존 preload와 renderer 산출물만 둔다. `app`은 런타임 의존성을 설치하지 않으므로 Forge의 Electron native rebuild 대상이 없다. `resources/node`에는 공식 SHA256으로 검증한 Node 24.18.0 실행 파일과 Node 라이선스를 둔다. `resources/engine`에는 루트 잠금 파일과 세 workspace 패키지 정보, contracts 및 engine의 JavaScript dist, 작업보호 실행 파일, `npm ci --omit=dev --ignore-scripts`로 설치한 production 의존성을 둔다. workspace 연결은 물리 디렉터리로 교체한다. 의존성의 설치된 LICENSE, COPYING, NOTICE 파일은 그대로 보존하고 버전 목록은 `의존성목록.json`에 기록한다.

대상 프로젝트, 사용자 자료, 비밀 값, 소스 `.runtime`은 복사하지 않는다. Forge의 `extraResource`가 `node`와 `engine`을 `app.asar` 밖의 `resources`에 둔다. Squirrel 이름과 앱 사용자 모델 ID는 `CheckMate` 및 `com.squirrel.CheckMate.CheckMate`다.

Squirrel 제작 도구는 실행별 `squirrel-vendor`에 복사한다. npm 설치에서 선택 스크립트를 건너뛴 환경을 위해 해당 실행 폴더에 x64용 `7z.exe`와 `7z.dll`을 준비한다. 이 도구 폴더는 포장 앱이나 설치 파일에 포함하지 않는다.

Squirrel에 동봉된 `rcedit.exe`는 한글 경로에 있는 `Setup.exe`를 열지 못한다. 제작 중에만 `.runtime/cm-<uuid>`라는 영문 연결 경로를 해당 실행 폴더에 만들고, Forge 출력을 그 경로로 지정한다. 실제 파일은 지정된 `.runtime/개발설치본/<uuid>` 안에 남으며 연결은 제작이 끝나면 해제한다.

## 설치 이벤트와 고정 CLI 경로

포장 앱의 main은 창과 단일 실행 잠금 전에 Squirrel 인자를 확인한다. `--squirrel-install`과 `--squirrel-updated`에서는 현재 실행 파일의 두 단계 상위 `Update.exe`를 `--createShortcut <현재 exe 이름>`으로 호출한다. `--squirrel-uninstall`에서는 `--removeShortcut <현재 exe 이름>`만 호출하고 `--squirrel-obsolete`에서는 별도 작업 없이 종료한다. 각 이벤트는 창을 열지 않으며 호출 실패를 오류로 남기고 비정상 종료한다. 제거 이벤트가 사용자 자료를 삭제하거나 다른 프로세스를 종료하지 않는다. `--squirrel-firstrun`은 일반 앱 실행으로 이어진다. [Electron Squirrel 안내](https://www.electronjs.org/docs/latest/api/auto-updater#squirrelwindows)와 설치된 `electron-winstaller/README.md`의 이벤트 예제를 따른다.

사용자 전용 자료 폴더에 소유 표시가 이미 있으면 포장 앱의 일반 실행 때 `bin/checkmate.cmd`를 현재 버전 경로로 갱신한다. 신규 자료 폴더에서는 사용자가 화면의 로컬 저장소 초기화에 동의하고 기존 초기화 경로가 성공한 직후 만든다. 이 명령 파일 생성은 저장소 초기화 동의나 프로젝트 실행 승인을 대신하지 않는다. 기존 파일은 CheckMate 자체 표시가 있는 일반 파일일 때만 갱신하며, 임시 파일을 동기화한 뒤 이름을 바꾼다. 자료 루트, `bin`, 명령 파일에는 기존 전용 자료와 같은 사용자 SID 제한 ACL을 적용한다. 진입점 생성에 실패하면 오류 대화상자를 표시하고 앱 화면은 계속 연다.

명령 파일은 현재 버전의 `resources/node/node.exe`와 `resources/engine/packages/engine/dist/명령.js` 절대 경로를 실행하고 `--data-dir`에 고정 자료 경로를 넘긴다. PATH는 자동 수정하지 않는다. 공백, 한글, 괄호가 있는 경로는 인용하고 명령 파일 안에서 UTF-8 코드 페이지를 잠시 지정한 뒤 원래 코드 페이지로 되돌린다. 경로에 `%`, `!`, `^`, `&`, `|`, `<`, `>`, 큰따옴표 또는 줄바꿈이 있으면 cmd 변수 확장과 제어문 해석을 막기 위해 파일 생성을 거절한다. 호출자가 넘기는 `%*` 인자는 호출자의 `cmd.exe` 규칙에 따라 해석되므로, 외부의 신뢰하지 않은 문자열을 셸 명령에 이어 붙이지 않는다. MCP 연결 정보는 기존처럼 동봉 Node의 절대 경로와 인자 배열을 제공하며 `checkmate.cmd`나 PATH를 사용하지 않는다.

현재 포장 파일의 `resources/node`와 `resources/engine`에는 실행 파일과 CLI가 이미 있다. 새 루트 `bin`이나 리소스 템플릿을 포장에 추가할 필요가 없고, main에 묶인 설치 연결 코드가 사용자 자료 폴더에 명령 파일을 만든다. 업데이트 뒤 새 버전 앱을 일반 실행하면 고정 명령 파일이 새 버전 경로를 가리킨다. 설치 이벤트 자체나 기존 실행 중 프로세스는 사용자 자료의 명령 파일을 갱신하거나 종료하지 않는다.

좁은 연결 시험은 `CHECKMATE_PACKAGED_RESOURCES`에 실제 포장 앱의 `resources` 절대 경로를 지정하고 `npx vitest run tests/설치연결.test.ts`로 실행한다. 시험은 새 합성 자료 위치에 고정 명령 파일을 만든 뒤 동봉 Node와 CLI의 `doctor`를 호출한다. 시스템 설치와 제거, 실제 업데이트 수용 시험은 이 시험에 포함되지 않는다.

## 결과와 수용 범위

포장 앱은 `forge/CheckMate-win32-x64`에, 설치 파일은 `forge/make/squirrel.windows/x64/CheckMate-개발설치.exe`에 생성된다. Squirrel의 `RELEASES`와 전체 패키지 파일도 함께 생성된다. 보고서의 `signed: false`는 코드 서명이 없음을 뜻한다. 스크립트는 설치 파일을 실행하거나 기존 앱을 종료하지 않는다. 실제 설치, 첫 실행, 단일 인스턴스, 제거 및 재설치 수용 시험은 별도 작업으로 남는다.

Forge의 [programmatic API](https://www.electronforge.io/cli), [설정](https://www.electronforge.io/config/configuration), [Squirrel maker](https://www.electronforge.io/config/makers/squirrel.windows)를 기준으로 구성했다. `make`는 `package`를 선행하며 이 스크립트는 게시 API를 호출하지 않는다.
