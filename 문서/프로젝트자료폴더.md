# 프로젝트별 검사 자료 폴더.

프로젝트마다 검사 자료를 저장할 부모 폴더를 선택할 수 있다. 같은 프로젝트의 여러 작업 폴더는 이 설정을 공유하며 실제 파일은 프로젝트·저장 구획·작업 폴더·실행별로 나뉜다. 다른 프로젝트나 다른 관리 자료 저장소가 같은 부모 폴더를 선택해도 실행 파일을 섞지 않는다.

## 폴더 선택과 기존 자료 이전.

1. 앱에서 대상 프로젝트를 선택하고 프로젝트 자료 폴더 설정을 연다.
2. 저장할 부모 폴더를 선택한다. 선택 창을 취소하면 현재 설정을 유지한다.
3. 미리보기의 목적 위치, 실행 수, 파일 수, 용량을 확인한다. 선택한 프로젝트의 기존 검사 자료도 이전 대상이다.
4. 이전을 명시적으로 확인한다. CheckMate는 사본을 만들고 파일의 SHA256과 길이를 검증한 뒤 저장 위치를 전환한다.
5. 완료된 설정을 확인하고 새 검사 계획을 만든다. 이전 폴더를 가리키던 미접수 계획은 다시 승인해야 한다.

성공해도 기존 원본은 삭제하지 않는다. 파일을 복사하는 도중 실패하면 이전 위치를 유지하고 실패 사본도 보존한다. 연결이 끊겨 완료 여부를 모르면 같은 이전 작업의 상태를 확인한다. 새 작업을 자동으로 만들거나 재복사하지 않는다.

기본 위치로 돌아가는 작업도 미리보기와 확인을 거친다. 그 위치에 보존 원본이나 다른 자료가 있으면 충돌할 수 있으며 기존 파일을 덮어써 해결하지 않는다. 실행 중이거나 종료·정리·소유권이 확인되지 않은 자료가 있으면 이전을 진행하지 않는다.

## 저장하는 자료.

선택한 부모 아래에 `CheckMate/<projectId>/<namespaceId>/<workspaceId>/runs/<runId>` 구획을 사용한다. 로그, 결과와 검사 산출물을 실행별로 정리한다. 기본 위치를 사용하는 기존 자료는 내부 `runs/<runId>` 위치를 유지한다.

테스트가 생성하는 파일은 CheckMate가 전달한 `CHECKMATE_EVIDENCE_DIR`에 기록하도록 검사 스크립트를 연결해야 한다. 다른 경로를 하드코딩한 테스트의 파일까지 자동으로 찾아 옮기지는 않는다. 제한된 stdout·stderr 로그는 비밀 가림을 거쳐 보관하며 잘리거나 확인되지 않은 부분을 완전한 로그로 표시하지 않는다. 이미지·압축 파일 등 산출물의 목록과 해시를 보존하고 공개 가능한 본문과 제한된 파일을 구분한다.

새 검사 산출물의 자동 수집 한도는 파일당 8MiB, 128개, 합계 32MiB와 하위 폴더 깊이16이다. 명령의 stdout·stderr는 합계 256KiB 제한을 유지한다. 한도를 넘거나 파일이 바뀌면 조용히 누락한 채 전체 보관 성공으로 표시하지 않는다. 기존 자료 이전은 이 신규 수집 한도로 파일을 잘라내지 않고 원래 목록과 해시를 확인한다.

이 설정으로 프로젝트 소스 전체, 로그인 정보, 서비스 연결 비밀, 관리 SQLite 또는 일회용 시험 DB 전체가 이동하지는 않는다. 검사 자체의 통과 여부와 파일 수집·보관 성공 여부도 구분한다.

## 회사 PC에서 이어가기.

앱의 자료 백업 기능을 사용하면 외부 프로젝트 폴더의 등록 증거도 함께 묶는다. 백업 완료와 파일 검증 결과를 확인하고 회사에서 허용한 위치로 전달한다. 실행 중인 SQLite나 프로젝트 작업 폴더를 실시간 동기화하지 않는다.

복원은 새 빈 자료 폴더에서 진행한다. 복원한 사본은 그 PC의 자료 위치를 사용하며 집의 외부 폴더를 자동 재사용하지 않는다. 필요한 프로젝트 출력 폴더를 회사 PC에서 다시 선택한다. 회사에서 실제 실행·접근 권한을 확인하기 전에는 그 PC의 사용 검증이 끝난 것으로 보지 않는다.

구 서비스에 연결되어 이 기능이 표시되지 않거나 사용할 수 없으면 진행 중인 실행과 설치·연결 버전을 먼저 확인한다. 앱을 새로 실행했다는 이유만으로 기존 서비스가 교체됐다고 가정하지 않는다.
